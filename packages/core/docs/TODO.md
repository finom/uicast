## Engine + catalog cleanup (OSS-prep)

Cleanup items in `packages/core` surfaced during OSS-prep review. Each is independent of the others; pick up in any order. Items 4 + 5 are consequence work of the planned eviction of `ConfirmModal` / `EditModeOverlay` / `ErrorBoundary` / `ui/*` from core (engine ships no React UI, consumers thread it in) — track together when that lands.

- [ ] **Move `render/shared.ts` (`onClickSchema`, `pickClick`) out of core.** These are catalog event-payload helpers — `pickClick(MouseEvent) → { pageX, pageY, screenX, screenY, clientX, clientY }` and the matching Zod schema — not engine concerns. Zero consumers outside `packages/core` today (and no tests). Move to `packages/catalog`, drop the `render/shared` re-exports from `packages/core/src/index.ts`.
- [ ] **Move product-flow prompts (`getClarifyPrompt`, `getEditPrompt`, `promptUtils.ts`) out of the engine surface.** `getClarifyPrompt` + `getEditPrompt` (with their helpers in `promptUtils.ts`: `buildElementTreeSummary`, `extractSubtree`, `findParent`) are tied to a specific UX flow ("ask clarifying questions before generating", "regenerate just this subtree") — they're not part of the runtime engine. Only legacy `tablo` consumes them; `neat-report` doesn't. Either carve them into a `core/prompt-extras` subpath or push them down to a consumer package, leaving the engine's public surface as `getPrompt` + the LLM contract (`prompt/INSTRUCTIONS.md`).
- [ ] **Fold the two `utils/` directories into one.** `src/lib/utils.ts` holds only `cn` (clsx + tailwind-merge); `src/utils/utils.ts` holds `parseScope` + `buildElementsById`. `cn` is consumed only by `ui/*` (already marked for eviction) and catalog's UI primitives — it leaves the engine with `ui/*`. Once `cn` is gone, drop `src/lib/`, leaving a single `src/utils/`. Drop `clsx` + `tailwind-merge` from `packages/core/package.json` at the same time.
- [ ] **Decouple `createAIComponentRenderers` from `EditModeOverlay`.** Today the Renderer takes `editMode` / `onEdit` props and wraps its content in `<EditModeOverlay>`. Edit-mode is a product feature, not an engine concern. When `EditModeOverlay` evicts, that coupling goes — edit-mode becomes a consumer-supplied wrapper around the Renderer, and the `editMode` / `onEdit` props vanish from the engine entry point.
- [ ] **Decouple `createAIComponentRenderer` from `useConfirm`.** `createAIComponentRenderer.tsx` calls `useConfirm()` at every render and consults it for `setExpr.confirm`. That ties every renderer to the `ConfirmModalProvider` context. When `ConfirmModal` evicts, `confirm` becomes an injected callback (registry- or prop-supplied). Type fallout: `AssignableWithConfirmExpr` collapses back into `AssignableExpr` + a callback param — one less branded type in the public surface.
- [ ] **Drop the `op` field from chunks — derive root status structurally.** `op: "root" | "child"` is redundant: a chunk is a root iff no other chunk lists its `key` in `children`. Cheap to derive (one pass: `const childKeys = new Set(lines.flatMap(l => l.children ?? [])); const roots = lines.filter(l => !childKeys.has(l.key))`). Originally floated twice as a token-reduction win in session `bf1339ad` — ~6 tokens per chunk × N chunks adds up at 178-chunk apps — but never executed. Surgery: (a) drop `op` from both chunk types in `packages/core/src/types.ts`; (b) replace `line.op !== "root"` filter in `packages/core/src/render/createAIComponentRenderers.tsx:60` with the structural derivation; (c) same in `packages/core/src/prompt/promptUtils.ts:15`; (d) strip `op` instructions from `packages/core/src/prompt/INSTRUCTIONS.md` (lines ~15, 27, 90, 140) and rewrite the root-definition prose; decide whether to advertise multi-root to the LLM or keep the "exactly one root" simplification even though the runtime already supports many; (e) rewrite the re-emit guidance in `packages/core/src/prompt/getEditPrompt.ts` (lines 70, 72) which currently tells the LLM to use `op: "child"` for replacements; (f) strip `op` from every catalog example file (`packages/catalog/src/examples/{claudeLines,listLines,nastenkaLines,asyncLines,chartLines,countLines,formLines,tableLines}.ts`); (g) strip `op` from every test fixture (every `RecursiveRenderer.*.test.tsx` plus the two streaming-defaults tests added in this branch); (h) **Prisma migration** drops `PageComponent.op` column and `ComponentOp` enum (both `packages/neat-report/prisma/schema.prisma:382` + the doc comment at line 28; tablo's `schema.prisma:130` not touched since tablo is parts-bin only); (i) regenerate Prisma client + Zod schemas + vovk client. Existing `PageComponent` rows: data is dropped but harmless because rendering doesn't read `op` anymore (root is structurally derived). Trigger this **before** any new prompt engineering work — every dollar of saved input is worth more once daily generation volume picks up.

## Prompts & eval (core)

- [ ] **`acorn` footprint — back-end goal already met ✅; drop neat-report's dep at extraction.** The original premise (the server pulling `acorn` via `getPartialFnPrompt` → `eval/evaluate.ts` → `SafeEval`) is **resolved**: the prompt migration replaced `getPartialFnPrompt` with `getFunctionsPartialPrompt` in the **acorn-free** `core/src/prompt/`. neat-report's server (`AiService`) imports it via the deep alias `@core/prompt/*` (never the `@core` barrel), and its whole server graph — the four `@core/prompt/*` builders + `@catalog/render/defs` (`createAIComponentDef`, type-only `CombinedSpec`) — no longer reaches `SafeEval`. (Verified 2026-06-02.) **Residual, deferred to the OSS extraction:** the `acorn` entry in `packages/neat-report/package.json` is **not** droppable yet — the **browser** bundle reaches it legitimately through the render runtime (`/p/[id]` `RenderPageView` → `@catalog/render/renderers` `Renderer` → core `RecursiveRenderer` / `createAIComponentRenderer` → `evaluate` → `SafeEval` → `import * as acorn`). Because neat-report bundles core's raw TS source via the `@core/*` path alias, Turbopack must resolve `acorn` from neat-report's side (it's hoisted to root `node_modules/acorn` today; the explicit entry was the Turbopack workaround). Once `core` ships as a built `@ui-fired/core` package — neat-report depending on the published artifact, not the source — `acorn` becomes core's private transitive dep and the explicit neat-report entry is cleanly removable. Do it then.
