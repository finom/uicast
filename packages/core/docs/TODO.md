# TODO — ui-fired framework (core + react + catalog)

Working list for the open-source rendering framework: the framework-agnostic engine (`packages/core`), the React binding (`packages/react`), and the component catalog (`packages/catalog`) that together become **ui-fired**. Product-side todos (onboarding, auth, data-source runtime, pricing, compliance) live in the consuming app's own repo, not here.

Engine reference docs live beside this file: [`./SPEC.md`](./SPEC.md) (the layered format spec — model / streaming / encoding), [`./OVERVIEW.md`](./OVERVIEW.md) (engine runtime), [`./LINES.md`](./LINES.md) (line properties), [`./EXPRESSIONS.md`](./EXPRESSIONS.md) (expressions), [`./SCOPES.md`](./SCOPES.md) (reactive proxy) and [`./REACT.md`](./REACT.md) (the React binding), plus the LLM-facing contract at [`../src/prompt/INSTRUCTIONS.md`](../src/prompt/INSTRUCTIONS.md).

Paths below are repo-root-relative (e.g. `packages/core/src/...`); they rebase to the new repo root once core + catalog are extracted into the standalone `ui-fired` repo.

When an item ships, leave the section header in place and clear (or strike through) the item so the structure stays scannable.

## Engine features (core + react)

- [ ] **Add a `loading` property to the element schema — render the placeholder while truthy.** A new bare `Expression` field on `Fired.Element`, evaluated like `hidden`: a reactive site that re-runs when the `scopes.X.Y` paths it reads change. Where `hidden` keeps the element mounted but visually hidden (React `<Activity>`), `loading` instead renders the element's **placeholder** — the same placeholder (a component's own, else the host-supplied `components.placeholder`) already shown for not-yet-streamed children — in place of the real component while the expression is truthy, then swaps the real component back in when it goes falsy. Intended for "this data is fetching / refreshing — show a skeleton here" without unmounting or losing sibling state. Surfaces to touch: `packages/core/src/types.ts` (`loading?: Expression` on `Element`), [`LINES.md`](./LINES.md) (document beside `hidden`), [`EXPRESSIONS.md`](./EXPRESSIONS.md) (another reactive `expr` site), the React renderer `packages/react/src/render/RecursiveRenderer.tsx` (evaluate `loading`, render the placeholder when truthy — the placeholder + `RendererRegistry` machinery already exists), and the LLM contract (`INSTRUCTIONS.md` + the relevant prompt partial) so the generator knows when to emit it. Open questions: precedence when both `loading` and `hidden` are truthy (loading should win — a hidden element shows nothing anyway); whether the placeholder is the registry default or per-element configurable; and how an explicit `loading` reconciles with the **existing** async-`defaults` suspension (which already shows the placeholder while a mount-time promise resolves — `loading` generalizes that to any reactive condition, not just initial seeding).

## Prompts & eval (core)

- [ ] **`acorn` footprint — make it core's private transitive dep once core ships built.** The prompt builders in `core/src/prompt/` are **acorn-free** (`getFunctionsPartialPrompt` et al. never reach `SafeEval`), so a consumer's server graph that only composes prompts never pulls in `acorn`. The **browser** render path does reach it (`Renderer` → `RecursiveRenderer` / `createAIComponentRenderer` → `evaluate` → `SafeEval` → `import * as acorn`). While `core` ships as **raw TS** consumed via a path alias, a consumer's bundler has to resolve `acorn` itself, so the consumer must declare it explicitly. Once `core` ships as a **built** package, `acorn` becomes core's private transitive dep and consumers no longer declare it. Do it then.
- [ ] **Align core's LLM-facing prompts with `/caveman`.** The framework's prompt surface — `src/prompt/INSTRUCTIONS.md` (the element-model contract) plus the catalog-agnostic partial builders in `src/prompt/` — gets the same terse `/caveman` compression pass as the product prompts. Mirror of the product-side prompts item tracked in the consuming app's own repo; keep the two in lockstep so the engine contract and product prompts compress consistently.
- [x] ~~**SafeEval — compile memoization (P1) + strict-parse / function-body / compile-guard correctness (P2).**~~ Done — (P1) the compiled `new Function(...)` is memoized per context-key signature on the cache entry, so an expression re-evaluated with a stable context shape compiles once, not once per call. (P2) `validate()` now parses in **strict mode** (a `"use strict"` directive in the parse wrapper), so sloppy-legal / strict-illegal constructs (octal literals, `with`, duplicate params) are rejected at validate as `SafeEvalError` instead of throwing raw at compile; `new Function(...)` is wrapped in try/catch → `SafeEvalError` as a backstop; and statements are now allowed inside **function-expression** bodies, not just arrow bodies (`xs.map(function (n) { … })`). +6 tests, 134 green.
