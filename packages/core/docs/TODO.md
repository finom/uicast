## Engine + catalog cleanup (OSS-prep)

Cleanup items in `packages/core` surfaced during OSS-prep review. Each is independent of the others; pick up in any order. Items 4 + 5 are consequence work of the planned eviction of `ConfirmModal` / `EditModeOverlay` / `ErrorBoundary` / `ui/*` from core (engine ships no React UI, consumers thread it in) — track together when that lands.

- [ ] **Move `render/shared.ts` (`onClickSchema`, `pickClick`) out of core.** These are catalog event-payload helpers — `pickClick(MouseEvent) → { pageX, pageY, screenX, screenY, clientX, clientY }` and the matching Zod schema — not engine concerns. Zero consumers outside `packages/core` today (and no tests). Move to `packages/catalog`, drop the `render/shared` re-exports from `packages/core/src/index.ts`.
- [ ] **Move product-flow prompts (`getClarifyPrompt`, `getEditPrompt`, `promptUtils.ts`) out of the engine surface.** `getClarifyPrompt` + `getEditPrompt` (with their helpers in `promptUtils.ts`: `buildElementTreeSummary`, `extractSubtree`, `findParent`) are tied to a specific UX flow ("ask clarifying questions before generating", "regenerate just this subtree") — they're not part of the runtime engine. Only legacy `tablo` consumes them; `neat-report` doesn't. Either carve them into a `core/prompt-extras` subpath or push them down to a consumer package, leaving the engine's public surface as `getPrompt` + the LLM contract (`prompt/INSTRUCTIONS.md`).
- [ ] **Fold the two `utils/` directories into one.** `src/lib/utils.ts` holds only `cn` (clsx + tailwind-merge); `src/utils/utils.ts` holds `parseScope` + `buildElementsById`. `cn` is consumed only by `ui/*` (already marked for eviction) and catalog's UI primitives — it leaves the engine with `ui/*`. Once `cn` is gone, drop `src/lib/`, leaving a single `src/utils/`. Drop `clsx` + `tailwind-merge` from `packages/core/package.json` at the same time.
- [ ] **Decouple `createAIComponentRenderers` from `EditModeOverlay`.** Today the Renderer takes `editMode` / `onEdit` props and wraps its content in `<EditModeOverlay>`. Edit-mode is a product feature, not an engine concern. When `EditModeOverlay` evicts, that coupling goes — edit-mode becomes a consumer-supplied wrapper around the Renderer, and the `editMode` / `onEdit` props vanish from the engine entry point.
- [ ] **Decouple `createAIComponentRenderer` from `useConfirm`.** `createAIComponentRenderer.tsx` calls `useConfirm()` at every render and consults it for `setExpr.confirm`. That ties every renderer to the `ConfirmModalProvider` context. When `ConfirmModal` evicts, `confirm` becomes an injected callback (registry- or prop-supplied). Type fallout: `ConfirmableValueSourceAssignment` collapses back into `ValueSourceAssignment` + a callback param — one less branded type in the public surface.
- [x] ~~**Drop the `op` field from chunks — derive root status structurally.**~~ Done — `op` removed from both chunk types in `types.ts`; root now derived structurally in `createAIComponentRenderers` (collect every `children` key, roots = chunks nothing references); stripped from the LLM contract (`INSTRUCTIONS.md`), `DSL.md`, `SCOPES.md`, all 8 catalog example files, and every test fixture. The runtime already supported multi-root via the synthetic Fragment wrapper, so the "exactly one root" contract is kept as guidance while the derivation tolerates many. **Residual (downstream, in neat-report — NOT done here):** `PageComponent.op` + the `ComponentOp` enum in `prisma/schema.prisma` are now vestigial (always default; nothing reads them). Drop the column + enum and regenerate Prisma/Zod/vovk in a follow-up migration — harmless to leave for now since persistence never wrote `op` explicitly.
- [x] ~~**Drop the `kind` field + rename list fields (`each`/`as`/`keyBy`) — derive list-ness structurally.**~~ Done — `kind: "element" | "list"` removed from both chunk types; a chunk is now a list **iff** it carries `each` (presence-based, same move as root-ness). List fields renamed `itemsSource`→`each`, `itemScope`→`as`, `itemIdKey`→`keyBy`. Touched `types.ts` (union narrows via `"each" in chunk`), `RecursiveRenderer`, `extractDeps`, the synthetic-Fragment builder, the LLM contract (`INSTRUCTIONS.md`), `DSL.md`, `SCOPES.md`, all 8 catalog example files, and every test fixture. Typecheck + 124 tests green. `ChunkMeta.kind: "meta"` stays (out-of-band envelope, identified before the render union). **Residual (downstream, in neat-report — NOT done here; bigger than the `op` one):** persistence is coupled to the wire field names — `PageComponent.kind` (enum `ComponentKind`) + the `itemsSource`/`itemScope`/`itemIdKey` columns; the `AiService` persist loop reads `chunk.kind` and spreads chunk fields into columns by name; `RenderPageView` blind-casts rows back to `ChunkComponent[]`. Renaming/removing on the wire forces a coordinated Prisma migration (rename the 3 columns → `each`/`as`/`keyBy`, drop the `kind` column + `ComponentKind` enum) + zod/vovk regen + persist-loop/rebuild edits. Must land WITH `npm update ui-fired` (the installed git-dep snapshot is stale, so it can't be typecheck-verified until then). Fold it into the same migration as the `op`-column drop above.

(Verified 2026-06-02.) **Residual, deferred to the OSS extraction:** the `acorn` entry in `packages/neat-report/package.json` is **not** droppable yet — the **browser** bundle reaches it legitimately through the render runtime (`/p/[id]` `RenderPageView` → `@catalog/render/renderers` `Renderer` → core `RecursiveRenderer` / `createAIComponentRenderer` → `evaluate` → `SafeEval` → `import * as acorn`). Once `core` ships as a built `@ui-fired/core` package — neat-report depending on the published artifact, not the source — `acorn` becomes core's private transitive dep and the explicit neat-report entry is cleanly removable. Do it then.
