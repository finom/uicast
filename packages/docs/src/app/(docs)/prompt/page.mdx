# Assembling the prompt

The system prompt teaches five things: the output contract, how ambitious to be,
the expression language, the component menu, and the host functions. Each ships
as a **prompt-partial builder** — a self-contained block — from one of three
packages, and there is no assembler: your app composes them, since scope,
components, and functions depend on what you register.

Advertise what you mount: the definitions must match the implementations, and
the functions must match the array on `<RendererProvider>`. Build both from the
same values and they cannot drift.

## The convention

Every builder returns a block starting with its own `#` heading, with no leading
or trailing blank lines. Assembly is a join, and the join owns the
separators:

```ts
const system = [...parts].filter(Boolean).join("\n\n");
```

## The partials

| Builder | Package | Emits |
| --- | --- | --- |
| `getCommonInstructionsPartialPrompt()` | `@uicast/core/prompt` | The output contract — JSONL entries, keys and children, partial replacement — and the expression context: `scopes` / `evt` / `currentValue` and the host-function calling rule. |
| `getScopePartialPrompt({ kind, approxElements? })` | `@uicast/core/prompt` | How much to build on this surface. |
| `getComponentsPartialPrompt({ definitions })` | `@uicast/core/prompt` | The component menu, serialized from your [definitions](/def). |
| `getFunctionsPartialPrompt({ functions })` | `@uicast/core/prompt` | Names and signatures, from your [tools](/functions). |
| `getExpressionsPartialPrompt()` | `@uicast/core/prompt` | The `expr` syntax, the available methods and globals, and the [safety](/expr#two-modes) rules. |
| `getFencePartialPrompt()` | `@uicast/streamdown/prompt` | The chat-surface fence convention — see [Chat surfaces](#chat-surfaces). |

Every builder also takes **`note?`** — host-specific context rendered as that
section's trailing `## Note`, verbatim. Use the section it belongs to: an extra
scope you [inject](/react/renderer#extra-named-scopes) goes on
`getCommonInstructionsPartialPrompt` (it lands under `# Expression Context`), a
catalog convention on `getComponentsPartialPrompt`, a data caveat on
`getFunctionsPartialPrompt`.

**Components** serializes the [defs](/def) you register:

```ts
const StatDef = createComponentDefinition({
  name: "Stat",
  description: "A KPI display.",
  props: z.object({
    label: z.string().meta({ description: "The metric label" }),
  }),
});
```

`getComponentsPartialPrompt({ definitions: [StatDef] })` returns:

```
# Available Components

Stat

# Component Details

- Stat — A KPI display.
  Props:
    - label: string — The metric label
```

**Scope** says what a response *is*. `kind: "page"` asks for a complete page and
reads a terse request as the full version of it. `"widget"` is one embeddable
piece; `"answer"` is the compact UI that answers a question in conversation.

`getScopePartialPrompt({ kind: "answer", approxElements: 10 })` emits the rules
for that kind, then the size hint:

```
- Use the fewest elements that fully answer the question; skip page chrome (headers, navigation, filter bars) unless asked.
- Bind real data via host functions — the answer must show actual values, not placeholders.

A typical response on this surface is around 10 elements (JSONL lines) — treat this as a hint about ambition, not a quota.
```

**Expressions** carries the standing
[safety instruction](/expr#two-modes), so every assembly ships it
without the host adding anything. Its allow-list line is a slot in the authored
`EXPRESSIONS.md`:

```
- Available globals (use ONLY these — referencing any other global is rejected before the expression runs, not silently `undefined`): 🔴ALLOWED_GLOBALS🔴.
```

`getExpressionsPartialPrompt()` fills that token from the same `ALLOWED_GLOBALS`
table [Evaluator](/expr) checks against, so the two cannot go out of sync. A
test holds the rest of the section to the same standard: no method it advertises
is one the evaluator would refuse.

**Functions** renders the tool array. Its signature format,
[undeclared returns](/functions#undeclared-returns), and
[shared types](/functions#shared-types) are covered in
[Host functions](/functions).

## Order

The contract comes first, since everything else refines it; the rest follow in
the order the sections reference each other. In that order the headings are:

| Builder | Package | Headings it emits |
| --- | --- | --- |
| `getCommonInstructionsPartialPrompt()` | `@uicast/core/prompt` | `# Overview`, `# Output Format`, `# Rules`, `# Expression Context` |
| `getScopePartialPrompt()` | `@uicast/core/prompt` | `# Scope` |
| `getComponentsPartialPrompt()` | `@uicast/core/prompt` | `# Available Components`, `# Common Events` (only when hoisted), `# Component Details`, `# Shared Types` (only when hoisted) |
| `getFunctionsPartialPrompt()` | `@uicast/core/prompt` | `# Available Functions`, `# Function Details`, `# Shared Types` (only when there is something to hoist) |
| `getExpressionsPartialPrompt()` | `@uicast/core/prompt` | `# JavaScript Expressions` |
| `getFencePartialPrompt()` | `@uicast/streamdown/prompt` | `# Emitting UI` |

## Chat surfaces

On a chat surface the reply is Markdown, and the entries sit inside a
` ```uicast ` fence, rendered by the [Streamdown plugin](/streamdown).
`@uicast/streamdown/prompt` ships the matching `getFencePartialPrompt()`: the
fence syntax plus the conversation's [shared-state rules](/streamdown). Compose
it last. A raw-JSONL surface skips it.

## A complete assembly

The chat endpoint from the demo app:

```ts
import {
  getCommonInstructionsPartialPrompt,
  getComponentsPartialPrompt,
  getExpressionsPartialPrompt,
  getFunctionsPartialPrompt,
  getScopePartialPrompt,
} from "@uicast/core/prompt";
import { getFencePartialPrompt } from "@uicast/streamdown/prompt";
import { allDefinitions } from "@uicast/shadcn-catalog/defs";
import { tools } from "./tools";

const system = [
  getCommonInstructionsPartialPrompt(),
  getScopePartialPrompt({ kind: "answer" }),
  getExpressionsPartialPrompt(),
  getComponentsPartialPrompt({ definitions: allDefinitions }),
  getFunctionsPartialPrompt({ functions: tools }),
  getFencePartialPrompt(),
].join("\n\n");
```

A page-builder surface is the same stack with `kind: "page"` and no fence
partial.

## Edit and recovery turns

Two builders are not system-prompt partials. They produce **user-turn message
content**.

`getEditRequestPrompt({ request, missingKeys? })` drives edits. The host replays
the stored JSONL as an assistant turn, then sends this as the next user turn:

```ts
const messages = [
  { role: "assistant", content: storedLines.map((l) => JSON.stringify(l)).join("\n") },
  { role: "user", content: getEditRequestPrompt({ request: "Make the total large." }) },
];
```

The builder appends the delta convention, and the model answers with the delta
alone — here one line, reusing the key:

```jsonl
{"key":"total","component":"Text","props":{"expr":"({ text: scopes.root.total, variant: 'large' })"}}
```

Every other key is untouched, and a successful `seed` on a re-emitted key does
not re-run — new state belongs on a new key. `missingKeys` lists keys the stored
tree references but never received, the tail of a truncated generation, so the
model emits them fresh instead of keeping them by reference.

`getErrorRecoveryPrompt({ failures })` reports runtime failures back so the model
re-emits those elements corrected. On a page it goes through the edit pipeline
above; in a chat it is a plain user message. See
[Error recovery](/error-recovery).
