# Assembling the prompt

The system prompt is built from **prompt-partial builders**, one block each.
There is no assembler: your app joins the blocks, since scope, components and
functions depend on what you register.

Advertise what you mount: build the prompt from the same definitions and
functions the page uses, so the two cannot drift.

## The convention

Each block starts with its own `#` heading and has no blank lines around it, so
assembly is a join:

```ts
const system = [...parts].filter(Boolean).join("\n\n");
```

## The partials

| Builder | Package | Emits |
| --- | --- | --- |
| `getCommonInstructionsPartialPrompt()` | `@uicast/core/prompt` | The output contract (JSONL entries, keys, children, partial replacement) and the expression context (`scopes`, `evt`, `currentValue`, how to call host functions). |
| `getScopePartialPrompt({ kind, approxElements? })` | `@uicast/core/prompt` | How much to build on this surface. |
| `getComponentsPartialPrompt({ definitions })` | `@uicast/core/prompt` | The component menu, serialized from your [definitions](/def). |
| `getFunctionsPartialPrompt({ functions })` | `@uicast/core/prompt` | Names and signatures, from your [tools](/expr/functions). |
| `getExpressionsPartialPrompt()` | `@uicast/core/prompt` | The `expr` syntax, the available methods and globals, and the [safety](/security#what-stays-your-job) rules. |
| `getFencePartialPrompt()` | `@uicast/streamdown/prompt` | The chat fence convention; see [Chat surfaces](#chat-surfaces). |

Every builder also takes **`note?`**: host-specific text, added verbatim as the
section's trailing `## Note`. Put it on the section it belongs to: an
[injected scope](/react/renderer#extra-named-scopes) on
`getCommonInstructionsPartialPrompt`, a catalog convention on
`getComponentsPartialPrompt`, a data caveat on `getFunctionsPartialPrompt`.

**Components** serializes the [defs](/def) you register:

```ts
const StatDef = createComponentDefinition({
  name: "Stat",
  description: "A KPI display.",
  props: z.strictObject({
    label: z.string().meta({ description: "The metric label" }),
  }),
});
```

`getComponentsPartialPrompt({ definitions: [StatDef] })` returns:

```
# Available Components

Stat

# Component Details

- Stat — A KPI display.
  Props:
    - label: string — The metric label
```

**Scope** says what a response *is*: `"page"` a complete page, even for a terse
request; `"widget"` one embeddable piece; `"answer"` a compact UI that answers a
question in a conversation.
`getScopePartialPrompt({ kind: "answer", approxElements: 10 })` emits:

```
- Use the fewest elements that fully answer the question; skip page chrome (headers, navigation, filter bars) unless asked.
- Bind real data via host functions — the answer must show actual values, not placeholders.

A typical response on this surface is around 10 elements (JSONL lines) — treat this as a hint about ambition, not a quota.
```

**Expressions** always includes the
[safety instruction](/security#what-stays-your-job). Its globals line is a
template slot:

```
- Available globals (use ONLY these — referencing any other global is rejected before the expression runs, not silently `undefined`): 🔴ALLOWED_GLOBALS🔴.
```

It is filled from the list the [Evaluator](/expr) checks against. A test fails
if the section advertises a method the evaluator refuses.

**Functions** renders the tool array. Its format,
[undeclared returns](/expr/functions#undeclared-returns) and
[shared types](/expr/functions#shared-types) are covered in
[Host functions](/expr/functions).

## Order

The contract comes first; the rest follow in the order they reference each
other. The headings each block emits:

| Builder | Package | Headings it emits |
| --- | --- | --- |
| `getCommonInstructionsPartialPrompt()` | `@uicast/core/prompt` | `# Overview`, `# Output Format`, `# Rules`, `# Expression Context` |
| `getScopePartialPrompt()` | `@uicast/core/prompt` | `# Scope` |
| `getComponentsPartialPrompt()` | `@uicast/core/prompt` | `# Available Components`, `# Common Events` (only when hoisted), `# Component Details`, `# Shared Types` (only when hoisted) |
| `getFunctionsPartialPrompt()` | `@uicast/core/prompt` | `# Available Functions`, `# Function Details`, `# Shared Types` (only when hoisted) |
| `getExpressionsPartialPrompt()` | `@uicast/core/prompt` | `# JavaScript Expressions` |
| `getFencePartialPrompt()` | `@uicast/streamdown/prompt` | `# Emitting UI` |

## Chat surfaces

On a chat surface the reply is Markdown, with entries inside a ` ```uicast `
fence that the [Streamdown plugin](/streamdown) renders.
`getFencePartialPrompt()` teaches the fence and the conversation's
[shared-state rules](/streamdown). Compose it last; a raw-JSONL surface skips
it.

## A complete assembly

The chat endpoint from the demo app:

```ts
import {
  getCommonInstructionsPartialPrompt,
  getComponentsPartialPrompt,
  getExpressionsPartialPrompt,
  getFunctionsPartialPrompt,
  getScopePartialPrompt,
} from "@uicast/core/prompt";
import { getFencePartialPrompt } from "@uicast/streamdown/prompt";
import { defs } from "@uicast/shadcn-catalog/all/defs";
import { tools } from "./tools";

const system = [
  getCommonInstructionsPartialPrompt(),
  getScopePartialPrompt({ kind: "answer" }),
  getExpressionsPartialPrompt(),
  getComponentsPartialPrompt({ definitions: defs }),
  getFunctionsPartialPrompt({ functions: tools }),
  getFencePartialPrompt(),
].join("\n\n");
```

A page-builder surface is the same stack with `kind: "page"` and no fence
partial.

## Edit and recovery turns

Two builders produce **user-turn messages**, not system-prompt partials.

`getEditRequestPrompt({ request, missingKeys? })` drives edits. The host replays
the stored entries as an assistant turn, then sends this as the next user turn:

```ts
const messages = [
  { role: "assistant", content: storedLines.map((l) => JSON.stringify(l)).join("\n") },
  { role: "user", content: getEditRequestPrompt({ request: "Make the total large." }) },
];
```

The builder appends the delta convention, and the model answers with the delta
alone, here one line reusing the key:

```jsonl
{"key":"total","component":"Typography","props":{"expr":"({ text: scopes.root.total, variant: 'large' })"}}
```

Other keys are untouched. A re-emitted key's `seed` does not re-run if it
already succeeded, and a seed never overwrites existing state: new state goes on
a fresh path or is written from a callback. `missingKeys` lists keys
the stored tree references but never received, as after a truncated
generation, so the model emits them.

`getErrorRecoveryPrompt({ failures })` reports runtime failures so the model
re-emits the broken elements: on a page through the edit pipeline above, in a
chat as a plain user message. See [Error recovery](/error-recovery).
