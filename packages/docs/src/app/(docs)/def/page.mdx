# Component definition

A catalog component is a **pair**: `def.ts` is the half the model reads,
`impl.tsx` the half React runs (React today; a definition is
framework-agnostic, and another binding would pair it with its own
implementation). An [entry](/entry/fields)'s
[`component`](/entry/fields#component), [`props`](/entry/fields#props), and
[`callbacks`](/entry/fields#callbacks) all point into the definition — it is the
contract saying a component exists, what props it takes, and what events it
sends. Everything the model knows about a component comes from here.

```ts
interface ComponentDefinition {
  name: string;          // catalog name the model emits — PascalCase, unique
  description: string;   // prose the model reads to decide when to use it
  props: StandardSchemaV1 & StandardJSONSchemaV1; // the props object
  callbacks?: Record<string, StandardSchemaV1 & StandardJSONSchemaV1>; // event → payload
  hidden?: boolean;      // kept out of the model's prompt, still renderable
}
```

`props` and every callback must be a `StandardSchemaV1 & StandardJSONSchemaV1`
(from [`@standard-schema/spec`](https://standardschema.dev), aliased
`CombinedSpec` in core): a runtime validator that also converts to JSON Schema.
The JSON Schema is printed into the prompt as a TypeScript-like signature. The
implementation receives the actual type, inferred from the same schema.

Zod 4.2+, Valibot and ArkType all qualify; the examples use Zod.

```ts filename="src/uicast-catalog/badge/def.ts"
import z from "zod";
import { createComponentDefinition } from "@uicast/core";

export const BadgeDef = createComponentDefinition({
  name: "Badge",
  description:
    "A small status indicator badge for labels, counts, or tags. Use it for " +
    "status (active, pending), categories, counts, or any short label.",
  props: z.strictObject({
    text: z.string().optional().meta({ description: "The badge text content" }),
    variant: z
      .enum(["neutral", "info", "warning", "danger"])
      .default("neutral")
      .meta({ description: "Visual style: neutral, info, warning, danger" }),
  }),
});
```

## `name`
The exact string the model writes in an entry's
[`component`](/entry/fields#component) field — **PascalCase**, unique across the
catalog. The renderer maps it to the implementation; the prompt builder lists it
under `# Available Components`. Two defs sharing a name throw
`Duplicate component name: "Badge"`.

## `description`
The model's whole briefing on the component: it reads this to decide *when* to
use it, and the text lands word for word on the `- Badge — …` line below.

## `props` — the contract with the model
Whatever you put in the schema, the model sees. Omit it for a component that
takes none, like a layout wrapper. `getComponentsPartialPrompt` turns the def
above into:

```
- Badge — A small status indicator badge for labels, counts, or tags. Use it for status (active, pending), categories, counts, or any short label.
  Props:
    - text?: string — The badge text content
    - variant?: "neutral" | "info" | "warning" | "danger" = "neutral" — Visual style: neutral, info, warning, danger
```

Describe **every** field with `.meta` — an undescribed one prints as a bare type,
and the model is left guessing which variant a paid order wants.
`.default("neutral")` marks `variant` optional for the model, prints as `=
"neutral"` so the model knows what omitting it gives, and supplies that value
when an entry does omit it — props are parsed through this schema before
[`render`](/react/impl) sees them, so the implementation just reads `variant`.

An entry's [`props`](/entry/fields#props) then has to produce that shape:

```jsonc
{ "key": "order-status", "component": "Badge",
  "props": { "expr": "({ text: scopes.root.order.status, variant: scopes.root.order.status === 'paid' ? 'neutral' : 'danger' })" } }
```

Use `z.strictObject`: a prop the model invented fails the element into its
error slot instead of being silently dropped — visible and correctable, the
same way a wrong-typed prop already fails. The shipped catalog is strict
throughout.

**Never `children`.** That name is the entry field listing child element keys, so
a def declaring it as a prop throws on creation. Name the prop for what it holds
— `text`, `title`, `label`. Nested elements still reach the implementation as
React `children` — see [`impl.tsx`](/react/impl).

## `callbacks` — event payloads
An optional map of event name to payload schema. Each declares the shape of
`evt` inside that callback's [steps](/entry/fields#callbacks) — the exact fields
available when the model writes `{ "expr": "evt.value" }`.

```ts
createComponentDefinition({
  // …
  callbacks: {
    onChange: z.strictObject({
      value: z.string().meta({ description: "The current value" }),
    }),
    onClear: z.null().meta({ description: "Clear button clicked" }),
    onKeyDown: keyboardEventSchema,
  },
});
```

With `keyboardEventSchema` registered as a common event, that block renders as:

```
  Event handlers:
    - onChange(evt)
      - value: string — The current value
    - onClear() — Clear button clicked
    - onKeyDown(evt: KeyboardEvent)
```

That block is the only reason the model can write this:

```jsonc
{ "key": "search", "component": "SearchInput",
  "props": { "expr": "({ value: scopes.root.q })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.q", "expr": "evt.value" }] } }
```

A callback carrying nothing is **`z.null()`**, which prints as a no-argument
call:

```
  Event handlers:
    - onPress() — Fires when pressed
```


The implementation follows the same schema —
`render: ({ onPress }) => <button onClick={() => onPress()}>Press</button>`.
Every declared callback is callable even if no entry wired it; an unwired
handler is a no-op, so implementations never guard.

### Shared events
`onClick` fires from a dozen components, and its payload would print on each of
them. Write it once, with a JSON Schema `$id`:

```ts
// src/uicast-catalog/events/keyboard.ts
export const keyboardEventSchema = z
  .object({
    key: z.string().meta({ description: 'The key value (e.g. "Enter", "a")' }),
    repeat: z.boolean().meta({ description: "Whether the key is auto-repeating" }),
  })
  .meta({ $id: "KeyboardEvent", description: "Fires on a key press" });

// in every def that fires it
createComponentDefinition({
  // …
  callbacks: { onKeyDown: keyboardEventSchema },
});
```

The `$id` is the whole signal — `getComponentsPartialPrompt` finds it on the
callback and hoists the payload automatically, nothing else to pass. The fields
now print once, and each handler is one line — `onKeyDown(evt: KeyboardEvent)`:

```
# Common Events

- KeyboardEvent — Fires on a key press
  - key: string — The key value (e.g. "Enter", "a")
  - repeat: boolean — Whether the key is auto-repeating
```

A payload with no `$id` prints inline under every handler instead. Two callbacks
naming the same `$id` with different payloads throw at assembly — a shared `$id`
must mean one shape.

The implementation still owes that exact payload, since a React event object is
not it:

```tsx
createComponentImplementation({
  // …
  render: ({ onKeyDown }) => (
    <input onKeyDown={(e) => onKeyDown({ key: e.key, repeat: e.repeat })} />
  ),
});
```

## `hidden` — keep a def out of the prompt
`hidden: true` keeps a def out of the prompt while leaving it in the renderer's
registry: an entry naming it still mounts, but the model is never told it
exists. The engine's own RootFragment uses it.

## Registration
A definition does nothing until it is registered twice: once for the prompt,
once for the renderer.

```tsx
import { getComponentsPartialPrompt } from "@uicast/core/prompt";
import { EntriesRenderer, RendererProvider } from "@uicast/react";
import { allDefinitions } from "@uicast/shadcn-catalog/defs";
import { allImplementations } from "@uicast/shadcn-catalog/impls";
import { BadgeDef } from "./badge/def";
import { BadgeImpl } from "./badge/impl";

getComponentsPartialPrompt({ definitions: [...allDefinitions, BadgeDef] });

<RendererProvider evaluator={evaluator} implementations={[...allImplementations, BadgeImpl]}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

Register only the def and the model emits a `Badge` that lands in the
[`error` slot](/error-recovery) as `reason: "unknown-component"`; register only
the impl and the model was never told the component exists.
