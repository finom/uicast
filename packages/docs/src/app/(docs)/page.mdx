**uicast is a UI framework whose language is written by models, not people.**
It gives a language model what JSX gives a developer — components, state,
events. The difference: JSX is designed to be easy for a person to maintain,
uicast to be reliable for a model to generate.

The model writes one JSON object per line. The engine places each line in the
tree and wires it to a reactive state store, and the result is a working
front-end app. The lines are just data, so there is no build or deploy step per
page.

What makes uicast different is **expressions**.

Other frameworks pick one of two options. Either the model writes real code,
which can do anything but is unsafe to run without a sandbox. Or it fills a
fixed schema, which is safe, but every behaviour must be built into the host in
advance.

uicast sits in between. The document is plain JSONLines, and computed values,
visibility, and event handling are short JavaScript expressions checked against
an [allow-list](/entry/expressions#safety) before they run. Nothing the model
writes becomes code you ship: it never defines a component, imports a module,
or adds a file. The largest thing it writes is **one expression**.

```js
// scopes.root.orders === [{ total: 2 }, { total: 3 }]
scopes.root.orders.reduce((a, o) => a + o.total, 0)  // ✅ → 5
listOrders()                                         // ✅ a host function you registered,
                                                     //    callable in seed and callbacks
fetch("/api/orders")                                 // ❌ throws — "fetch" is not
                                                     //    available in expressions
document.cookie                                      // ❌ throws — so do "window",
                                                     //    "localStorage", "eval", …
```

| Approach | Predictability | Expressiveness | Safety |
| --- | --- | --- | --- |
| Raw code generation | low | unlimited | low |
| **uicast** | high | high | high |
| Structured generation ([json-render](https://github.com/vercel-labs/json-render), [A2UI](https://a2ui.org)) | deterministic | limited | guaranteed |

## The model works from a developer's brief

The model never starts from a blank page. It gets the brief you would give a new
front-end developer: here are the components, here are the endpoints, build the
page. Both lists are generated from your code:

```md
# Available Components

Card, Heading, Text, Badge, Button, Table, TableRow, TableCell

# Common Events

- MouseEvent — Callback for a mouse event such as a click
  - clientX: number — The X coordinate of the pointer relative to the viewport
  - …

# Component Details

- Button — A clickable button for triggering actions. …
  Props:
    - text?: string — The button label text
    - variant?: "default" | "destructive" | "outline" | … — Visual variant
    - disabled?: boolean — Whether the button is disabled
  Event handlers:
    - onClick(evt: MouseEvent)

… one entry per component …

# Available Functions

listOrders, refundOrder

# Function Details

- listOrders() => {
    id: number /* Order id */;
    customer: string /* Who placed it */;
    total: number /* Order total, in dollars */;
  }[]: Every order, newest first.
- refundOrder({
    id: number /* Order id */;
  }) => unknown: Refund one order.
```

> Show this week's orders, with a refund button on each row.

Both lists are fixed. The **catalog** is your design system, already built and
reviewed — the model picks from it and cannot invent a component. The
**functions** are your endpoints, each a
[`standard-tool`](https://standard-tool.js.org/), and it cannot call anything
else.

Every description is one you already wrote on a schema field or a prop, passed
through word for word. Nothing repeats: a shared payload is printed once under
`# Common Events` and referred to as `evt: MouseEvent`, and a shared type once
under `# Shared Types`.

A developer with this brief writes JSX; the model writes uicast entries. See
[Assembling the prompt](/prompt).

## Events carry payloads

An event can carry data, not just report that something happened. The square
below sends the pointer position as an `onMove` payload; the entry writes it to
state, and the props read it back. No host function is involved.

Inside a callback, **`evt` is that payload** — the only way to read what the
user just did. Its shape is whatever the [definition](/def) declares, so
`onMove` here means `evt.x` and `evt.y` are numbers. `evt` exists only in
`callbacks`, never in `props`, `hidden`, or `seed`.

## Calling host functions

Expressions can call **host functions** — the functions you register with the
renderer, and how a document reaches a backend. Each is a
[`standard-tool`](https://standard-tool.js.org/): a name, a description,
schemas, and `execute`.

`getWeather` below is **async**, about 500 ms. Picking a city runs a two-step
callback: the first stores the city, the second calls
`getWeather({ city: scopes.root.city })` and reads the path the first just
wrote, so the runtime orders them. The engine waits for the result before
writing it, which is why the card can show a loading state and why the
expression never says `await`.

## Streaming a generation

Each line renders as soon as it is complete, so the page builds itself while the
model is still writing. TanStack Query's `streamedQuery` turns an
`AsyncIterable` into an array that grows as values arrive — which is what
`streamJsonLines` returns and what the renderer takes:

```tsx
const { data: lines = [], isFetching } = useQuery({
  queryKey: ["generate", prompt],
  queryFn: streamedQuery({
    streamFn: async () => {
      const res = await fetch("/api/generate", {
        method: "POST",
        body: JSON.stringify({ prompt }),
      });
      return streamJsonLines<ComponentEntry>(res.body);
    },
  }),
});

<EntriesRenderer entries={lines} />   // grows line by line; isFetching is the spinner
```

The model writes parents before children, so the page fills in from the top: a
Card appears under its title with a placeholder where its child will go.
Finished parts are never rebuilt, and a `seed` that already fetched does not
fetch again.
