# The expression evaluator

A model writes every `expr`, and a saved document replays in other people's
browsers, so an expression is untrusted input. `@uicast/expr` runs it.

The language is **JavaScript expressions over JSON data**: the standard
methods of strings, numbers and arrays and a short list of globals, without
statements, `new`, mutation, regular expressions or function values. The
package has no **uicast** dependency.

## How an expression runs

`Evaluator` parses an expression once with acorn and runs it itself, checking
every property read and every call under a CPU and allocation
[budget](#budgets). No source reaches the JavaScript engine, so a strict
Content-Security-Policy without `unsafe-eval` works.

```tsx
import { Evaluator } from "@uicast/expr";

const evaluator = new Evaluator({ functions });

<RendererProvider evaluator={evaluator} /> // the React binding
```

The checks happen at run time, because a name can be built while the
expression runs:

```js
"abc".substr(1)            // refused — `substr` is not in the language
"abc"["sub" + "str"](1)    // the same call — the name exists only at run time
```

Under `Evaluator` the call itself is checked, so both lines are refused. Three
rules do most of the work:

- **Own properties only.** Nothing inherited is readable, so
  `({}).constructor{:ts}` is `undefined`. No deny-list is needed.
- **Only data is readable.** Objects, arrays, primitives, a short list of
  built-ins. A class instance, a DOM node or a function fails on the first
  read, so a real `MouseEvent` in scope cannot leak `evt.target.ownerDocument`.
- **Methods are called, never passed around.** `rows.map` as a value is an
  error.

## Where expressions appear

Every site, in one product search (`scopes.root.products` is seeded higher up):

```jsonc
{ "key": "search", "component": "SearchInput",
  "seed": [{ "set": "scopes.root.query", "literal": "" }],
  "props": { "expr": "({ value: scopes.root.query })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.query", "expr": "evt.value" }] } }
{ "key": "empty", "component": "Typography", "hidden": "scopes.root.products.length > 0",
  "props": { "literal": { "text": "No products" } } }
{ "key": "rows", "component": "Typography", "as": "row", "keyBy": "id",
  "each": "scopes.root.products.filter(p => p.name.includes(scopes.root.query))",
  "props": { "expr": "({ text: scopes.row.name })" } }
```

`props` is a [value source](/entry/value-sources); `hidden`, `loading` and
`each` are bare strings. Inside `callbacks`, an expression also sees `evt`. A `set` step
also sees [`currentValue`](/entry/value-sources#valuesourceassignment), the
value at that path now.

Only `seed` and `callbacks` await a result, so only they may call host
[`functions`](/expr/functions). A host call in `props`, `hidden`, `loading` or `each` is
rejected into the error slot.

A scope path read in `props`, `hidden`, `loading` or `each` subscribes the element to it.
Paths are read from the expression text, not declared, so write them out
literally: see [Reactivity &amp; Dependencies](/entry/reactivity).

## The language

The grammar is a closed allow-list of AST node types; anything else fails
validation.

| | |
| --- | --- |
| Values | numbers, strings, booleans, `null`, template literals |
| Access | `a.b`, `a[b]{:ts}`, `a?.b{:ts}`, `a?.[b]{:ts}` (optional *receiver*, not `a?.(){:ts}`) |
| Calls | methods, host functions |
| Operators | arithmetic, comparison, `===`/`==`, `&&`, `\|\|`, `??`, `!`, `-`, `+`, `typeof`, `? :` |
| Literals | arrays and objects, with spread and computed keys |
| Functions | arrow functions with an **expression body**, only as a method's callback; parameters may destructure |

Left out on purpose:

- **Statements and declarations.** No `const`/`let`/`var`, loops, `try`,
  blocks or `function`. A runaway loop cannot be written, and with nothing
  named, nothing can recurse.
- **Assignment, `++`, `delete`, mutating methods.** Expressions are **pure by
  construction**: only a step's `set` changes state. Use `.toSorted(){:ts}` and
  `.toReversed(){:ts}` instead of `.sort(){:ts}` and `.reverse(){:ts}`.
- **Regular expressions.** Catastrophic backtracking runs outside the budget.
  Use `.includes(){:ts}`, `.startsWith(){:ts}`, `.split(){:ts}` or `.replaceAll(){:ts}`.
- **Functions as values.** An arrow is only a method's callback, as in
  `rows.map(r => r.name){:ts}`: never stored, returned or called. A global that
  takes one argument can replace it: `rows.filter(Boolean){:ts}`.
- **`await`.** The runtime awaits a host call, so the call must be the result:
  the whole expression, a branch of `?:`, or the right side of `??`, `||`,
  `&&`. `getUser({ id }).name{:ts}` and `ids.map(id => getUser({ id })){:ts}` are
  refused before any call runs.
- **`Intl`.** The locale methods still take a locale and options:
  `price.toLocaleString(undefined, { style: "currency", currency: "USD" }){:ts}`.
- **`new`, so `Date` values, `Set` and `Map`.** Every value is JSON. A date is
  an ISO string or a timestamp from `Date.parse(text){:ts}` or `Date.now(){:ts}`; format
  it in a component (see
  [`DateTime`](https://github.com/finom/uicast/tree/main/packages/shadcn-catalog/src/uicast-catalog/date-time)).
  An object does a `Map`'s job, and
  `Object.keys(Object.groupBy(rows, r => r.tag)){:ts}` lists distinct tags.
- **`forEach`, iterators.** Callbacks have no effects, and functions are not
  values.
- **`in`, bitwise operators, `x?.(){:ts}`, `instanceof`, tagged templates, `this`.**
  None shapes a display value.

A callback body is one expression too, never a block:

```js
// ✅ a ternary inside the callback
scopes.root.rows.map(r => r.status === "paid" ? "green" : "red")

// ❌ rejected — a block body is a statement list, and there are no statements
scopes.root.rows.map(r => { switch (r.status) { case "paid": return "green" } })
```

Expressions are also **stateless**: no `Math.random` (a random value comes
from a host function) and nowhere to keep a counter. `Date.now(){:ts}` changes on
every re-evaluation, so take it once in a step and read it back:

```jsonc
// ❌ a new timestamp every render pass
{ "props": { "expr": "({ text: 'Draft ' + Date.now() })" } }

// ✅ produced once, read back from the path
{ "seed": [{ "set": "scopes.root.draftId", "expr": "Date.now()" }],
  "props": { "expr": "({ text: 'Draft ' + scopes.root.draftId })" } }
```

`getExpressionsPartialPrompt(){:ts}` gives the model these rules and the globals,
filled from the evaluator's own tables.

<Callout type="default">
  Control flow lives in the document, not in expressions: sequencing in a
  callback's ordered steps, iteration in `each`, conditionals in `hidden`.
</Callout>

## Budgets

Every expression stops: evaluation throws when the budget runs out. Only
built-in methods iterate, and `Evaluator` implements each one, so every
iteration is charged:

- a **step counter** (1,000,000 by default): a callback invocation costs its
  body's node count, a call costs its work (a sort about n·log n steps);
- a **wall-clock deadline** (100 ms), on a clock the expression cannot read or
  move;
- **allocation caps**, so `"x".repeat(1e9){:ts}` is refused, not attempted;
- an **AST depth limit**, so nested source cannot overflow the compiler;
- a **source-length limit** (`maxSourceLength`, 1000 characters by default),
  checked before parsing. The prompt states it to the model.

The step counter is the contract. Each operation is priced by its measured
time, and a test keeps each within 4× a plain step, so a long evaluation stops
at the same step on any device. The clock is a backstop: in Chrome at 6× CPU
slowdown (a mid-range phone) the step limit still fires first; at 12×, locale
formatting or comparing two long strings can reach the clock first.

## When an expression is rejected

A rejection is a classified
[`EntryError`](/error-recovery#classification-entryerror-and-onerror), a
**document** fault shown in the element's error slot:

| expression | reason |
| --- | --- |
| `if (scopes.root.n) 1{:ts}` | `expression-syntax` — a statement, not an expression |
| `scopes.root.count = 1{:ts}` | `guardrail-violation` — assignment is not in the language |
| `scopes.root.rows["so" + "rt"](){:ts}` | `guardrail-violation` — checked at the call, computed or not |
| `fetchProducts(){:ts}` | `unknown-reference` — a name nobody handed in |

## Performance

Measured with `npx vitest bench --run --root packages/expr{:bash}`:

| expression | in a document | `Evaluator` |
| --- | --- | --- |
| `scopes.root.count > 0{:ts}` | a `hidden` condition | ~80 ns |
| `scopes.root.user.name` | any scope read | ~115 ns |
| template, two interpolations | a text prop | ~255 ns |
| object literal from scope | every `props.expr` | ~260 ns |
| `filter`, `map`, `reduce` over 1000 rows | a derived list | 28–63 µs |
| re-evaluate a whole 1000-row table, 5 expressions per row | the realistic worst case | ~0.79 ms |

The prompt bounds the load: `maxListItems` on
`getCommonInstructionsPartialPrompt` (default 100) tells the model to cap
visible lists and page or filter past that. **Expressions shape display
values; host functions compute.**

Whole events (every expression one event re-evaluates) in Chrome on an M4 Pro,
then with the CPU slowed 6× and 12×:

| event | M4 Pro | 6× slower | 12× slower |
| --- | --- | --- | --- |
| 50-row table, 7 cells per row | 0.3 ms | 1.3 ms | 4.5 ms |
| 100-row table, currency and date formatting per row | 0.4 ms | 2.5 ms | 5.1 ms |
| dashboard over 1,000 orders: 3 KPIs, a chart, a 30-day series | 1.6 ms | 11 ms | 21 ms |
| search keystroke over 1,000 orders | 1.1 ms | 7.1 ms | 16 ms |
| the same over 10,000 orders | 9.8 ms | 60 ms | 123 ms |
| kanban board, 300 cards | 0.2 ms | 3.5 ms | 3.5 ms |
| join 1,000 orders to 200 customers with `find(){:ts}` per order | 5.2 ms | 33 ms | 68 ms |

A frame is 16 ms. Two kinds of work belong in a host function: the whole
table in the browser, and a search per row.

## What it does not secure

An expression reaches only the contexts and the functions bound at
construction; `window`, `fetch` and everything else are out of reach. The
interpreter secures the language, not these:

- **Host functions are capabilities.** A callback can call any function you
  bound, with any input its schema accepts: `deleteProduct({ id: 42 }){:ts}` deletes
  product 42. Keep `functions` narrow and authorize on the server.
- **Props that reach the DOM.** The browser may fetch a URL a document
  controls on render. The renderer's
  [`urlPolicy`](/react/renderer#urlpolicy--the-urls-a-document-may-load) gates
  those props.
- **What you put into scope.** The membrane refuses non-data values; tools
  with an `outputSchema` pass only parsed data.

More, including the
[catalog-authoring contract](/react#props-the-document-controls), is on
[Security model](/security).

## Verification

`@uicast/expr` has one runtime dependency (acorn) and no `new Function`. Every
rule is an allow-list held as data in `src/constants/`, and a test keeps the
runtime tables and the README's language section equal to it.

- **Against JavaScript.** `corpus.test.ts` runs each expression in `Evaluator`
  and as plain JavaScript; both must return the same value or both throw
  (*differential testing*). The likely bug is not an escape but a drift from
  JavaScript (`"" == 0{:ts}`, `-0{:ts}`, coercion order). `baseline.test.ts` repeats the
  corpus on an ES2022 engine with newer built-ins deleted.
- **Against known attacks.** `attacks.test.ts` asserts that known escapes
  reach nothing: `constructor` through a computed key, prototype pollution,
  allocation bombs, recursion tricks, a live object in scope.
- **Through the engine.** `hooks.test.ts` runs the corpus through a
  `new Function` subclass and pins what it gives up:
  `"abc"["sub" + "str"](1){:ts}` returns `"bc"{:ts}`.
- **Other controls.** `exit-gate.test.ts` (only plain data leaves),
  `host-functions.test.ts` (the tool boundary), `prototype-exposure.test.ts`
  (null-prototype tables), `prices.test.ts` (step prices).

<Callout type="warning">
  Any evaluator of untrusted expressions can have implementation bugs. A
  grammar small enough to review, tested differentially and adversarially,
  bounds that risk; it does not remove it. `Evaluator` closes the computed-key
  class and needs no `unsafe-eval`.
</Callout>
