# Streamdown plugin

`@uicast/streamdown` puts generated UI inside a Markdown chat reply. In the
raw-JSONL setup from [Streaming](/streaming) the whole output is entries. On a
chat surface the reply is Markdown, and the entries sit inside a fenced code
block tagged `uicast`:

````md
Here's this month's revenue at a glance:

```uicast
{"key":"root","component":"Card","seed":[{"set":"scopes.root.orders","expr":"listOrders()"}],"children":["stat"]}
{"key":"stat","component":"Stat","props":{"expr":"({ label: 'Revenue', value: scopes.root.orders.length })"}}
```

The stat is live — it recomputes from the database on every view.
````

[Streamdown](https://streamdown.ai/) (2.5+) renders Markdown as it streams and
lets a plugin claim a fence language. This package is that plugin: `uicast`
blocks mount as an [`<EntriesRenderer>`](/react/renderer) under your chat's
`<RendererProvider>`, and every other fence stays highlighted code.

The language token does all the routing, so the
[fence prompt partial](/prompt#chat-surfaces) tells the model to use `uicast`
and no other token.

```bash
npm install @uicast/streamdown@beta streamdown
```

## `createFenceRenderer`

```ts
import type { CustomRenderer } from "streamdown";

function createFenceRenderer(options?: FenceRendererOptions): CustomRenderer;

type FenceRendererOptions = {
  /** Show a Rendered/Source switcher above each block. Default false. */
  showSourceToggle?: boolean;
  /** Render blocks in a server pass too. Default false. */
  ssr?: boolean;
};
```

Implementations, the evaluator, and fallback UI all come from the
[`<RendererProvider>`](/react/renderer) around your conversation. The entries
come from the fence: each completed line mounts immediately, and a partial last
line waits for its newline.

```tsx
import { Streamdown } from "streamdown";
import { RendererProvider } from "@uicast/react";
import { createFenceRenderer } from "@uicast/streamdown";
import * as catalogImpls from "@uicast/shadcn-catalog/all/impls";
import { Evaluator } from "@uicast/expr";
import { tools } from "./tools";

const evaluator = new Evaluator({ functions: tools });
const fenceRenderer = createFenceRenderer();
const impls = Object.values(catalogImpls);

export function Chat({ replies }: { replies: string[] }) {
  return (
    <RendererProvider implementations={impls} evaluator={evaluator}>
      {replies.map((markdown, i) => (
        <Streamdown key={i} plugins={{ renderers: [fenceRenderer] }}>
          {markdown}
        </Streamdown>
      ))}
    </RendererProvider>
  );
}
```

**The conversation is one app.** Every block under one `<RendererProvider>`
shares the same `root` scope. The fence at the top of this page seeds
`scopes.root.orders`; a later reply writes the same path:

```jsonl
{"key":"root","component":"Button","seed":[{"set":"scopes.root.orders","expr":"listOrders()"}],"props":{"literal":{"text":"Refresh"}},"callbacks":{"onClick":[{"set":"scopes.root.orders","expr":"listOrders()"}]}}
```

Click Refresh and the `Stat` in the earlier block updates. Both fences name an
element `root` — keys are per-fence, only state is shared.

**Every block seeds everything it reads**, even when an earlier block already
seeded it. That repeat is deliberate: it is what lets any block be saved as a
standalone page.

**Blocks render after hydration**, so a server-rendered chat page shows an empty
fence until the browser takes over, unless [`ssr`](#ssr) is on.

## `showSourceToggle`

With `showSourceToggle: true`, each block gets a **Rendered / Source** switcher.
The block stays mounted while Source is shown, so switching back does not reset
its state. Off by default — a development aid, not something end users need.

## `ssr`

With `ssr: true`, blocks also render in a server pass: their seeds run and host
functions are called on the server, so those must work there. Off by default.

## Wrappers that forward `plugins`

Chat kits that wrap Streamdown — e.g. AI Elements' response component — usually
apply their own default plugin set and spread your props over it. Passing
`plugins` there **replaces** the defaults, so recompose them alongside the
fence renderer:

```tsx
const plugins = { cjk, code, math, mermaid, renderers: [fenceRenderer] };

<MessageResponse plugins={plugins}>{part.text}</MessageResponse>
```

## The prompt side

Rendering is half the contract; the model also has to know to emit the fence.
`@uicast/streamdown/prompt` exports `getFencePartialPrompt()`, which teaches the
fence syntax and the shared-state rules: one `root` scope across every block,
first-writer-wins seeding, and partial replacement only within a fence. Compose
it after the core partials — see [Assembling the prompt](/prompt).
