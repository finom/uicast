# Value Sources

A **value source** is how an entry expresses one value: static, or computed from
a JavaScript expression. Three forms:

```ts
ValueSource                      = { expr } | { literal }             // props
ValueSourceAssignment            = ValueSource & { set }              // seed steps
ConfirmableValueSourceAssignment = ValueSource & { set?, confirm? }   // callback steps
```

A callback step may **drop `set`** and run purely for its effect; a `seed` step
never can.

[Entry fields](/entry/fields) covers which field takes which form.

## ValueSource

A value, given one of two ways.

```jsonc
{ "literal": "Hello" }           // any JSON value, used as-is
{ "expr": "scopes.root.title" }  // a JavaScript expression, evaluated against the scopes
```

`expr` takes any [JavaScript expression](/expr).

## ValueSourceAssignment

A `ValueSource` plus a `set`: evaluate, then **write the field** `set` names,
`scopes.<scope>.<field>`. Never deeper, never a number — `scopes.root.rows.0.qty`
is rejected; edit a row through its scope or replace the array
([why](/entry/state#reading-and-writing)).

```jsonc
{ "set": "scopes.root.count", "literal": 0 }
{ "set": "scopes.root.itemCount", "expr": "scopes.cart.items.length" }
{ "set": "scopes.root.count", "expr": "currentValue + 1" }  // read-modify-write
{ "set": "scopes.root.open", "expr": "!currentValue" }      // unset → undefined → true
```

**`currentValue`** is whatever sits at the `set` path now — the value about to
be replaced. It makes an assignment a read-modify-write without naming the path
twice. `set` is what defines it, so in a bare
[`props`](/entry/fields#props), [`hidden`](/entry/fields#hidden), or
[`each`](/entry/fields#each) expression it does not exist:

```jsonc
// ❌ no `set` here — throws: "currentValue" is not available in expressions
{ "hidden": "!currentValue" }
```

How the write lands depends on the site. A `callbacks` step overwrites. A `seed`
step is **first-writer-wins**: it assigns only if the path is still
`undefined`:

```jsonc
{ "key": "filters", "component": "Card", "children": ["status-input"],
  "seed": [{ "set": "scopes.root.status", "literal": "open" }] }
{ "key": "status-input", "component": "Input",
  "seed": [{ "set": "scopes.root.status", "literal": "all" }],
  "props": { "expr": "({ value: scopes.root.status })" } }
```

The input renders `open`. The parent seeds before the child mounts, so the
child's write is a silent no-op — two entries seeding one path never clobber
each other (see [state](/entry/state#lifecycle)). The same `set` in a
`callbacks` step would write `all`.

## ConfirmableValueSourceAssignment

`confirm` gates the step behind a confirmation message.

```jsonc
{ // …
  "callbacks": { "onClick": [
    { "expr": "deleteUser({ id: scopes.row.id })",
      "confirm": "Delete this user? This cannot be undone." },
    { "set": "scopes.root.users", "expr": "listUsers()" }
  ] } }
```

No `set` on the first step, so the delete's return value is discarded. Decline
the prompt and neither step runs. A confirmed step is also an
[ordering barrier](/entry/reactivity): everything before it settles first, and
nothing after it starts until it passes.
