# Entry fields

A **uicast** document is JSONLines: one JSON object per line, each an **entry**
describing one element. The engine mounts entries into a tree by key reference.
The dynamic fields are JavaScript [expressions](/expr) over the document's
[scopes](/entry/state).

Every field but `loading`, used once:

```jsonl
{"key":"task-card","component":"Card","props":{"literal":{"title":"Tasks"}},"seed":[{"set":"scopes.root.tasks","expr":"listTasks()"}],"children":["task-rows","empty-note","refresh"]}
{"key":"task-rows","component":"Typography","each":"scopes.root.tasks","as":"task","keyBy":"id","props":{"expr":"({ text: scopes.task.title })"}}
{"key":"empty-note","component":"Typography","hidden":"scopes.root.tasks.length > 0","props":{"literal":{"text":"No tasks yet"}}}
{"key":"refresh","component":"Button","props":{"literal":{"text":"Refresh"}},"callbacks":{"onClick":[{"set":"scopes.root.tasks","expr":"listTasks()"}]}}
```

`task-card` is the root: no `children` array mentions it.

```ts
interface ComponentEntry {
  key: string;          // unique id — required
  component: string;    // catalog component name — required
  props?: ValueSource;  // the props object
  hidden?: Expression;  // truthy → hidden
  loading?: Expression; // truthy → busy
  children?: string[];  // child keys, in render order
  seed?: ValueSourceAssignment[];  // initial state, once at mount
  callbacks?: Record<string, CallbackValueSourceAssignment[]>;  // event → steps
  each?: Expression;    // array to iterate — its presence marks a list
  as?: string;          // per-item scope name
  keyBy?: string;      // per-item identity field
}
```

## Structure

### `key`
**Required.** A unique id, in **kebab-case** (`"user-card"`, never
`"userCard"`). Parents name children by it, and re-emitting a `key`
[replaces that subtree](#partial-replacement) in place.

```jsonc
{ "key": "user-card", "component": "Card" }
```

### `component`
**Required.** The catalog name, matched exactly against the renderer's
registry:

```jsonc
{ "key": "user-card",  "component": "Card" }      // ✅ in the catalog
{ "key": "user-panel", "component": "UserCard" }  // ❌ Unknown component: UserCard
```

An unknown name renders the element's [error slot](/error-recovery); the rest of
the document is unaffected.

### `children`
The child `key`s, in render order. Absent or empty means a leaf:

```jsonl
{"key":"row","component":"FlexRow","children":["name","email"]}
{"key":"name","component":"Typography","props":{"literal":{"text":"Ada Lovelace"}}}
{"key":"email","component":"Typography","props":{"literal":{"text":"ada@example.com"}}}
```

`children` is reserved: a [definition](/def) may not declare it as a prop. Text
goes in a prop named for what it holds, `text` above.

## Value and state

### `props`
A [value source](/entry/value-sources) giving the props object, static or
computed (wrap an object literal in parens). It is a **reactive site**: the
engine subscribes to every path the expression reads. See
[Reactivity](/entry/reactivity).

```jsonc
{ "props": { "expr": "({ text: scopes.root.title })" } }
{ "props": { "literal": { "variant": "outline" } } }
```

Props that fail the [definition](/def)'s schema raise `invalid-props` in the
element's error slot, before render.

### `hidden`
A bare [expression](/expr), with no `literal` form, that hides the element while
truthy. Reactive, like `props`.

```jsonl
{ "key": "details-switch", "component": "Switch",
  "seed": [{ "set": "scopes.root.showDetails", "literal": false }],
  "props": { "expr": "({ checked: scopes.root.showDetails, label: 'Details' })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.showDetails", "expr": "evt.checked" }] } }
{ "key": "details-note", "component": "Textarea", "hidden": "!scopes.root.showDetails",
  "seed": [{ "set": "scopes.root.draft", "literal": "" }],
  "props": { "expr": "({ value: scopes.root.draft })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.draft", "expr": "evt.value" }] } }
```

`hidden` does not unmount: it hides the subtree inside React's
[`<Activity>`](https://react.dev/reference/react/Activity).

### `loading`

A bare expression, like `hidden`. While it is truthy the element is busy: the
React binding hands it to the implementation as
[`context.loading`](/react#the-render-function). Set it from the callback that
refetches:

```jsonc
{ "key": "rows", "component": "Table", "loading": "scopes.root.busy", "children": ["head", "body"] }
{ "key": "search", "component": "SearchInput", "callbacks": { "onChange": [
  { "set": "scopes.root.q", "expr": "evt.value" },
  { "set": "scopes.root.busy", "literal": true, "debounce": true },
  { "set": "scopes.root.rows", "expr": "listRows({ q: scopes.root.q })" },
  { "set": "scopes.root.busy", "literal": false }
] } }
```

The host call is a barrier, so the flag clears after the rows land. A first
load through `seed` shows the [skeleton](/react#skeleton) instead; `loading`
is for refreshes.

### `seed`
An array of [assignments](/entry/value-sources#valuesourceassignment) that
**initialize scope paths once**, when the element first mounts.

```jsonc
{ "seed": [{ "set": "scopes.root.users", "expr": "getUsers()" }] }
```

- **Runs once, on success.** Re-renders and partial replacement do not re-run
  it. A failed seed never landed, so a corrected re-emission seeds normally.
- **Seed state, not derivations.** Seed values that change later: form fields,
  selections, fetched lists. Compute derived values in `props`, `hidden` or
  `each`; a seed would freeze them at mount time.
- **Dependent seeds work.** Steps run in [dependency waves](/entry/reactivity):

  ```jsonc
  { "seed": [
    { "set": "scopes.root.tz",       "literal": "UTC" },
    { "set": "scopes.root.users",    "expr": "getUsers()" },
    { "set": "scopes.root.selected", "expr": "scopes.root.users[0].id" }
  ] }
  ```

  `tz` and `users` run in parallel. `selected` reads what `users` writes, so it
  waits for `getUsers()`. See [lifecycle](/entry/state#lifecycle).

### `callbacks`
A map from event name to an ordered list of
[steps](/entry/value-sources#callbackvaluesourceassignment), run when the
component fires that event. A step is an assignment, optionally confirmed or
debounced.

```jsonc
{ "callbacks": {
  "onChange": [
    { "set": "scopes.root.q", "expr": "evt.value" },
    { "set": "scopes.root.results", "expr": "searchTasks({ q: scopes.root.q })" }
  ]
} }
```

- **Steps run in [dependency order](/entry/reactivity).** A step that reads a
  path an earlier step wrote waits for it; independent steps run in parallel;
  a [host-function](/expr/functions) step runs alone in its wave.
- **`evt`** is the event payload, shaped by the component's
  [definition](/def).
- **`currentValue`** is the value now at the step's `set` path, and
  **`confirm`** gates a step behind a Yes/No prompt:

  ```jsonc
  { "callbacks": {
    "onClick": [
      { "set": "scopes.root.expanded", "expr": "!currentValue" },
      { "confirm": "Delete this task?", "expr": "deleteTask({ id: scopes.task.id })" }
    ]
  } }
  ```

  The delete step has no `set`, so it runs only for its effect. Answering No
  skips it and every step after.

## List fields

An entry with `each` is a **list**: its `component` renders once per item.
There is no list container; the parent that names the list supplies it:

```jsonl
{"key":"task-table","component":"Table","children":["task-body"]}
{"key":"task-body","component":"TableBody","children":["task-row"]}
{"key":"task-row","component":"TableRow","each":"scopes.root.tasks","as":"task","keyBy":"id","children":["task-num","task-title"]}
{"key":"task-num","component":"TableCell","props":{"expr":"({ text: scopes.task.$$index + 1 })"}}
{"key":"task-title","component":"TableCell","props":{"expr":"({ text: scopes.task.title })"}}
```

Three tasks give one `<tbody>` with three `<tr>`s. The list's `children` repeat
with it, each copy reading its own `scopes.task`.

### `each`
A bare [expression](/expr) returning the array to repeat over. Reactive: a
write to a path it reads re-runs the list.

```jsonc
{ "each": "scopes.root.orders" }                                   // a state array
{ "each": "scopes.root.orders.filter(o => o.status === 'open')" }  // derived — still re-runs on every write to orders
```

An `each` that evaluates to `undefined` renders zero rows, not an error.

### `as`
The item's scope name, on the list entry and its whole subtree. `scopes.<as>` is
the item itself, plus `$$index` and `$$id` (from [`keyBy`](#keyby)); a
primitive item is read as `$$value`. See
[State &amp; Scopes](/entry/state#item-scopes).

Scope names are one flat namespace, so `as` **must be globally unique**. Reused
in a nested list, the inner one hides the outer:

```jsonc
{ "key": "order-row", "each": "scopes.root.orders", "as": "row", "children": ["line-item"] }
{ "key": "line-item", "each": "scopes.row.lines", "as": "row" }
// ❌ inside line-item, scopes.row is the line — the order it belongs to is unreachable
```

### `keyBy`
Where `$$id`, the stable identity per item, comes from:

```jsonc
{ "each": "scopes.root.tasks", "as": "task", "keyBy": "id" }  // { id: 7 } → 7; an item with no `id` falls back to its index
{ "each": "scopes.root.tasks", "as": "task" }                 // no keyBy → ids 0, 1, 2 …
```

**Give object items a stable key.** Without one, in-place edits shift rows and
lose their per-item state.

## Partial replacement

Re-emitting an entry whose `key` exists **replaces it and its subtree in
place**. It is the only patch verb, used for mid-stream corrections and
[edit turns](/prompt#edit-and-recovery-turns). The new entry's `children`
decide what survives. Already streamed:

```jsonl
{"key":"task-card","component":"Card","children":["task-rows","refresh"]}
{"key":"task-rows","component":"Typography","each":"scopes.root.tasks","as":"task","keyBy":"id","props":{"expr":"({ text: scopes.task.title })"}}
{"key":"refresh","component":"Button","props":{"literal":{"text":"Refresh"}}}
```

Later in the same stream:

```jsonl
{"key":"task-card","component":"Card","children":["refresh","task-rows","empty-note"]}
{"key":"empty-note","component":"Typography","props":{"literal":{"text":"No tasks yet"}}}
```

`refresh` and `task-rows` are not re-emitted, but the new `children` name them,
so they survive with their subtrees, reordered. A key left out of `children` is
dropped: omission is the delete.

State seeded above the replaced subtree is untouched, and the re-emitted
entry's `seed` does not re-run, so state the user changed survives. Use this to
fix or restructure emitted UI; ongoing updates go through [`set`](/entry/state).
