# Reactivity & Dependencies

You never declare what an expression depends on. Every `scopes.<scope>.<path>`
access is extracted by static analysis — the same parser that checks the
expression for [safety](/entry/expressions#safety) — and that read set drives
two different mechanisms, depending on where the expression sits.

## Reactive sites: subscriptions

`props.expr`, `hidden`, and `each` re-evaluate when state changes. Each read
becomes a subscription, and a write re-renders exactly the elements reading that
path.

```jsonl
{"key":"count","component":"Text","props":{"expr":"({ text: scopes.root.products.length + ' products' })"}}
```

`count` subscribes to `scopes.root.products.length`. A write to that path or any
path above it notifies it; a write below it does not. So only the first of these
re-renders `count`:

```jsonc
{ "set": "scopes.root.products", "expr": "listProducts()" }     // ✅ replaces the array
{ "set": "scopes.root.products.0.name", "literal": "Renamed" }  // ❌ stays asleep
```

One expression can produce several subscriptions. Two entries from a larger
document, whose ancestor seeds `scopes.root.products`:

```jsonl
{"key":"search","component":"SearchInput","seed":[{"set":"scopes.root.query","literal":""}],"props":{"expr":"({ value: scopes.root.query })"},"callbacks":{"onChange":[{"set":"scopes.root.query","expr":"evt.value"}]}}
{"key":"rows","component":"Text","each":"scopes.root.products.filter(p => p.name.includes(scopes.root.query))","as":"row","keyBy":"id","props":{"expr":"({ text: scopes.row.item.name })"}}
```

`rows` subscribes to `scopes.root.products` (a method call truncates the path, so
the dependency is the array, not the call) and to `scopes.root.query`. Neither
entry mentions the other. Typing writes `query`, and the list re-filters.

## Effectful sites: ordering

`seed` and `callbacks` run once per trigger, so their read sets drive
**ordering** instead. Steps are split into dependency waves: a step reading a
path an earlier step wrote — including through
[`currentValue`](/entry/value-sources#valuesourceassignment) — lands in a later
wave, and independent steps share one.

```jsonc
{ // …
  "seed": [
    { "set": "scopes.root.city", "literal": "Amsterdam" },
    { "set": "scopes.root.weather", "expr": "getWeather({ city: scopes.root.city })" }
  ] }
```

Two waves: `weather` reads `city`, so it waits. Give the second step nothing to
wait for and both share one wave, running in parallel:

```jsonc
{ // …
  "seed": [
    { "set": "scopes.root.products", "expr": "listProducts()" },
    { "set": "scopes.root.categories", "expr": "listCategories()" }
  ] }
```

Callbacks add two barriers the scan cannot infer. A step calling a
[host function](/functions) waits for everything before it, since a mutation's
effect is invisible. A `confirm` step is a barrier in both directions:

```jsonc
{ // …
  "callbacks": { "onClick": [
    { "expr": "deleteProduct({ id: scopes.row.item.id })", "confirm": "Delete this product?" },
    { "set": "scopes.root.products", "expr": "listProducts()" }
  ] } }
```

Two waves, never one: step one carries `confirm`, step two calls a host
function. The refetch reads nothing the delete writes, so path analysis alone
would have run them together.

## Keep paths static

Extraction is static, so the runtime only sees paths written out literally:

```jsonl
{"key":"selected","component":"Text","props":{"expr":"({ text: scopes.root.rows[scopes.root.sel].name })"}}
```

Two paths are extracted: `scopes.root.rows` and `scopes.root.sel`. The path the
key *resolves* to is not, so writing `scopes.root.rows.2.name` leaves `selected`
asleep. Write the path you mean.

## No dependency loops

A reactive site cannot write. `props`, `hidden` and `each` only compute; state is
written only by a `seed` step at mount or a `callbacks` step on an event, and
neither re-runs because a render happened. The React failure — an effect writing
state it also reads — has no path here.

An implementation can still do it: a `useEffect` that calls one of its callbacks
on every render loops like any React component.
