# State & Scopes

All state lives in **scopes**: a flat namespace of reactive containers that
expressions read and `set` writes. An expression addresses state by scope name
and field:

```
scopes.<scopeName>.<field>     // e.g. scopes.root.searchTerm
```

## What a scope is

A scope is one shallow `Proxy` over a set of fields, with no state library
underneath. Everything under a field is plain data. `root` and the scopes you
add are [`createProxyScope`](/api-ref#uicastcore) objects; an item scope is the
runtime's own ([below](#item-scopes)).

```ts
const root = createProxyScope<{ count: number; user?: { name: string } }>({ count: 0 });

root.$$emitter.on("user", () => { /* … */ });   // subscribe to a field

root.count = 1;                             // write — emits "count"
root.$$set("user", { name: "Ada" });         // the same, as a call
root.$$set("count", 0, { default: true });   // no-op — writes only if unset
root.user.name = "Hopper";                  // ❌ a plain write into plain data — nobody hears it
```

A write replaces one field and emits it. There is no deep write: to change part
of an object, write the object. A [`seed`](#lifecycle) step writes with
`default: true`, so two entries seeding one field do not overwrite each other.

## The root scope

`scopes.root` is always present and is the only app-wide scope: search terms,
the active tab, which modal is open.

```jsonc
{ "key": "search", "component": "SearchInput",
  "seed": [{ "set": "scopes.root.searchTerm", "literal": "" }],
  "props": { "expr": "({ value: scopes.root.searchTerm })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.searchTerm", "expr": "evt.value" }] } }
```

Every other scope belongs to a list item or comes from the host. `root` belongs
to the [`<RendererProvider>`](/react/renderer), not to one document, so every
document under one provider shares it. That is how chat [blocks](/streamdown)
share live state.

## Item scopes

A [list](/entry#list-fields) gives **each item its own scope**, named by `as`.
That scope *is* the item, a window onto the element in the array, plus three
read-only fields of the runtime's own.

```jsonc
{ "key": "orders", "component": "Card",
  "each": "scopes.root.orders", "as": "order", "keyBy": "id",
  "children": ["order-title"] }
{ "key": "order-title", "component": "Typography",
  "props": { "expr": "({ text: (scopes.order.$$index + 1) + '. ' + scopes.order.customer + ' #' + scopes.order.$$id })" } }
```

`$$index` is the zero-based position in the `each` result, and `$$id` the key
`keyBy` picked (the index without `keyBy`). When the array holds strings or
numbers, the item is `$$value`. The runtime computes all three on read. They
are never stored on the item, and a copy of the row, such as
`{ ...scopes.order }`, holds only the item's own fields.

**A write goes into the array.** `set: "scopes.order.status"` changes that
element inside `scopes.root.orders` and wakes everything reading the array.

**Scopes stack**, so names must be globally unique. A reused name does not
error; it silently shadows:

```jsonc
// ❌ the inner `as` overwrites the outer. Inside a line, `scopes.item` IS the
//   line, and the order it belongs to is unreachable.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "item", "children": ["lines"] }
{ "key": "lines", "component": "Typography", "each": "scopes.item.lines", "as": "item",
  "props": { "expr": "({ text: scopes.item.sku })" } }

// ✅ distinct names stack — a line sees root, order and line at once.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "order", "children": ["lines"] }
{ "key": "lines", "component": "Typography", "each": "scopes.order.lines", "as": "line",
  "props": { "expr": "({ text: scopes.order.id + ' / ' + scopes.line.sku })" } }
```

A row cannot write when its `each` built new objects
(`orders.map(o => ({ ...o, total }))`): the element is in no scope field, so the
write is refused as `unknown-reference`. Keep `each` on the data, or a `filter`
/ `toSorted` of it, and derive in `props`. A row of primitives cannot be written
at all; replace the array.

## Per-row state

State *about* a row that is not its data, such as expanded or selected, lives at
root, keyed by `$$id`:

```jsonc
{ "key": "page", "component": "Card",
  "seed": [{ "set": "scopes.root.expanded", "literal": {} }], "children": ["orders", "expand-all"] }
{ "key": "orders", "component": "Row", "each": "scopes.root.orders", "as": "order", "keyBy": "id",
  "props": { "expr": "({ open: scopes.root.expanded[scopes.order.$$id] ?? false })" },
  "callbacks": { "onToggle": [{ "set": "scopes.root.expanded",
    "expr": "({ ...currentValue, [scopes.order.$$id]: !currentValue[scopes.order.$$id] })" }] } }
{ "key": "expand-all", "component": "Button", "props": { "literal": { "text": "Expand all" } },
  "callbacks": { "onClick": [{ "set": "scopes.root.expanded",
    "expr": "scopes.root.orders.reduce((m, o) => ({ ...m, [o.id]: true }), {})" }] } }
```

One write to the map wakes every row, but only rows whose evaluated props
changed re-render.

## Reading and writing

- **Reads** are property access at any depth: `scopes.root.count`,
  `scopes.order.total`, `scopes.root.user.address.city`.
- **Writes happen only through `set`**, in a `seed` step at mount or a
  `callbacks` step on an event. See [assignments](/entry/value-sources).

A `set` address is `scopes.<scope>.<field>`: never deeper, never a number.

```jsonc
{ "set": "scopes.root.rows", "expr": "listRows()" }                                    // ✅ a field
{ "set": "scopes.root.filters", "expr": "({ ...scopes.root.filters, status: 'open' })" }  // ✅ part of a field: write the field
{ "set": "scopes.root.filters.status", "literal": "open" }                             // ❌ rejected — deeper than a field
{ "set": "scopes.root.rows.0.qty", "literal": 3 }                                      // ❌ rejected — a number
```

A write wakes every reader of the field, at any depth: writing `filters` wakes a
reader of `filters.status`. See [Reactivity](/entry/reactivity).

## Lifecycle

A seeded field persists for the life of the page, through re-renders and while
its element is `hidden`. A field never seeded reads as `undefined`.

A `seed` is **first-writer-wins**: it assigns only if the field is still
`undefined`.

```jsonc
{ "key": "panel", "component": "Card", "seed": [{ "set": "scopes.root.sort", "literal": "name" }],
  "children": ["label"] }
{ "key": "label", "component": "Typography", "seed": [{ "set": "scopes.root.sort", "literal": "price" }],
  "props": { "expr": "({ text: scopes.root.sort })" } }
```

Renders `name`: `panel` seeds before `label` mounts, so `label`'s seed is a
no-op, not an error. The same `set` in a `callbacks` step would write `price`.
This is also why a value the user changed survives a re-mount.

The host can also supply state.
[`<RendererProvider evaluator={evaluator} init>`](/react/renderer#init--preload-state-for-the-group)
preloads `scopes.root` once, before any entry evaluates, and can
[expose extra named scopes](/react/renderer#extra-named-scopes) (read as
`scopes.userCtx.name`): proxies the host keeps and can update later.

Declare each extra scope in the `note` of `getCommonInstructionsPartialPrompt`,
which lands as a `## Note` under the prompt's `# Expression Context`. The note
is all the model sees of the scope, so spell out its shape.
