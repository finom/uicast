# State & Scopes

All state lives in **scopes**: a flat namespace of reactive containers that
expressions read and `set` assignments write. An expression sees one variable,
`scopes`, and addresses state by scope name and field:

```
scopes.<scopeName>.<field>     // e.g. scopes.root.searchTerm
```

## What a scope actually is

Every scope is a `createProxyScope` object from [`@uicast/core`](/api-ref#uicastcore):
one shallow JavaScript `Proxy` over a bag of fields, no state library
underneath. Everything under a field is plain data.

```ts
const root = createProxyScope<{ count: number; user?: { name: string } }>({ count: 0 });

root.$$emitter.on("user", () => { /* … */ });   // subscribe to a field

root.count = 1;                             // write — emits "count"
root.$$set("user", { name: "Ada" });         // the same, as a call
root.$$set("count", 0, { default: true });   // no-op — writes only if unset
root.user.name = "Hopper";                  // ❌ a plain write into plain data — nobody hears it
```

A write replaces one field and emits it. There is no deep write: to change
part of an object, write the object. `default: true` is what a
[`seed`](#lifecycle) step uses so two entries seeding one field do not
overwrite each other.

## The root scope

`scopes.root` is always present, and is the only app-wide scope. Search terms,
the active tab, which modal is open — all here:

```jsonc
{ "key": "search", "component": "SearchInput",
  "seed": [{ "set": "scopes.root.searchTerm", "literal": "" }],
  "props": { "expr": "({ value: scopes.root.searchTerm })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.searchTerm", "expr": "evt.value" }] } }
```

Every other scope belongs to a list item or comes from the host. `root` belongs
to the [`<RendererProvider>`](/react/renderer), not to one document, so every
document under one provider shares it. On a chat surface that is what lets
[blocks](/streamdown) share live state.

## Item scopes

A [list](/entry#list-fields) renders its `component` once per item and
gives **each item its own scope**, named by `as`. That scope *is* the item: a
window onto the element in the array, plus three fields of the runtime's own.

```jsonc
{ "key": "orders", "component": "Card",
  "each": "scopes.root.orders", "as": "order", "keyBy": "id",
  "children": ["order-title"] }
{ "key": "order-title", "component": "Typography",
  "props": { "expr": "({ text: (scopes.order.$$index + 1) + '. ' + scopes.order.customer + ' #' + scopes.order.$$id })" } }
```

Over `[{ id: "a1", customer: "Ada" }, { id: "b2", customer: "Grace" }]` that is
`1. Ada #a1` then `2. Grace #b2`. `customer` is the element's own field;
`$$index` is the row's zero-based position in the `each` result, `$$id` the key
`keyBy` picked (the index when there is no `keyBy`). When the array holds
strings or numbers, the value is `$$value`. The three `$$` names are read-only.

**A write goes into the array.** `set: "scopes.order.status"` changes that
element inside `scopes.root.orders`, in place, and wakes everything reading the
array — totals, filters, the list. Two lists over one array are two windows onto
the same elements: an edit in one shows in the other.

**Scopes stack**, so names must be globally unique. Reusing one does not error —
it silently shadows:

```jsonc
// ❌ the inner `as` overwrites the outer. Inside a line, `scopes.item` IS the
//   line, and the order it belongs to is unreachable.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "item", "children": ["lines"] }
{ "key": "lines", "component": "Typography", "each": "scopes.item.lines", "as": "item",
  "props": { "expr": "({ text: scopes.item.sku })" } }

// ✅ distinct names stack — a line sees root, order and line at once.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "order", "children": ["lines"] }
{ "key": "lines", "component": "Typography", "each": "scopes.order.lines", "as": "line",
  "props": { "expr": "({ text: scopes.order.id + ' / ' + scopes.line.sku })" } }
```

Two things a row cannot do. It cannot write when its `each` built new objects
(`orders.map(o => ({ ...o, total }))`): the element is in no scope field, so the
write is refused as `unknown-reference`. Keep `each` on the data, or a `filter`
/ `toSorted` of it, and derive in `props`. And a row of primitives cannot be
written at all — replace the array.

## Per-row state

A row scope holds the row's data. State that is *about* a row but is not data —
expanded, selected — lives at root, keyed by `$$id`:

```jsonc
{ "key": "page", "component": "Card",
  "seed": [{ "set": "scopes.root.expanded", "literal": {} }], "children": ["orders", "expand-all"] }
{ "key": "orders", "component": "Row", "each": "scopes.root.orders", "as": "order", "keyBy": "id",
  "props": { "expr": "({ open: scopes.root.expanded[scopes.order.$$id] ?? false })" },
  "callbacks": { "onToggle": [{ "set": "scopes.root.expanded",
    "expr": "({ ...currentValue, [scopes.order.$$id]: !currentValue[scopes.order.$$id] })" }] } }
{ "key": "expand-all", "component": "Button", "props": { "literal": { "text": "Expand all" } },
  "callbacks": { "onClick": [{ "set": "scopes.root.expanded",
    "expr": "scopes.root.orders.reduce((m, o) => ({ ...m, [o.id]: true }), {})" }] } }
```

One write to the map wakes every row that reads it. Only the rows whose props
actually changed re-render: the renderer compares an element's evaluated props
with the last ones structurally and skips the implementation when they are
equal.

## Reading and writing

- **Reads** are plain property access inside an [expression](/expr), any depth:
  `scopes.root.count`, `scopes.order.total`, `scopes.root.user.address.city`.
- **Writes happen only through `set`**, on a `seed` or `callbacks`
  [assignment](/entry/value-sources). `seed` initializes a field at mount;
  `callbacks` update it on an event.

A `set` address is a scope name, a dot, a field name. Never a number, never
deeper — the set of valid addresses is a regular language, `scopes.<scope>.<field>`:

```jsonc
{ "set": "scopes.root.rows", "expr": "listRows()" }                                    // ✅ a field
{ "set": "scopes.root.filters", "expr": "({ ...scopes.root.filters, status: 'open' })" }  // ✅ part of a field: write the field
{ "set": "scopes.root.filters.status", "literal": "open" }                             // ❌ rejected — deeper than a field
{ "set": "scopes.root.rows.0.qty", "literal": 3 }                                      // ❌ rejected — a number
```

A write wakes every reader of that field, at whatever depth the reader goes:
writing `filters` wakes a reader of `filters.status`. See
[Reactivity &amp; Dependencies](/entry/reactivity).

## Lifecycle

A `seed` initializes a field when its element mounts, and it then persists for the
life of the page — through re-renders, and while the element is `hidden`. A field
that was never seeded reads back as `undefined`.

A `seed` is **first-writer-wins**: it assigns only if the field is still
`undefined`.

```jsonc
{ "key": "panel", "component": "Card", "seed": [{ "set": "scopes.root.sort", "literal": "name" }],
  "children": ["label"] }
{ "key": "label", "component": "Typography", "seed": [{ "set": "scopes.root.sort", "literal": "price" }],
  "props": { "expr": "({ text: scopes.root.sort })" } }
```

Renders `name`. `panel` seeds before `label` mounts, so `label`'s seed finds the
field defined and writes nothing — a no-op, not an error. The same `set` in a
`callbacks` step would write `price`. This is also why a value the user changed
survives a re-mount instead of snapping back.

State can also come from the host:
[`<RendererProvider evaluator={evaluator} init>`](/react/renderer#init--preload-state-for-the-group)
preloads `scopes.root` once, before any entry evaluates, and can
[expose extra named scopes](/react/renderer#extra-named-scopes)
(read as `scopes.userCtx.name`) — proxies the host keeps and can update later.

Declare any extra scope to the model too —
`getCommonInstructionsPartialPrompt({ note: "scopes.userCtx holds the signed-in user: name (string), plan ('free' | 'pro')." })`
appends it as a `## Note` right under the prompt's `# Expression Context`
section, so the
"invent no other scope" rule stays consistent with your setup. The note is all
the model ever sees of the scope, so spell out its shape in it.
