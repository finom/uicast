# State & Scopes

All state lives in **scopes**: a flat namespace of reactive containers that
expressions read and `set` assignments write. An expression sees one variable,
`scopes`, and addresses state by name and path:

```
scopes.<scopeName>.<path>     // e.g. scopes.root.searchTerm
```

## What a scope actually is

Every scope is a `createProxyScope` object from [`@uicast/core`](/api#uicastcore):
a native JavaScript `Proxy` over a plain object, no state library underneath.

```ts
const root = createProxyScope<{ count: number; user?: { name: string } }>({ count: 0 });

root.$emitter.on("user", () => { /* … */ });  // subscribe to a path

root.count = 1;                            // write — emits
root.user.name = "Ada";                    // ❌ throws — `user` is undefined
root.$set("user", { name: "Ada" });        // ✅ set the parent, then write into it
root.$set("count", 0, { default: true });  // no-op — writes only if unset
```

Reads are plain property access, and both write forms emit. `$set` adds the
dotted path, and `default: true`, which is what a [`seed`](#lifecycle) step uses
so two entries seeding one path do not overwrite each other.

## The root scope

`scopes.root` is always present, and is the only app-wide scope. Search terms,
the active tab, which modal is open — all here:

```jsonc
{ "key": "search", "component": "SearchInput",
  "seed": [{ "set": "scopes.root.searchTerm", "literal": "" }],
  "props": { "expr": "({ value: scopes.root.searchTerm })" },
  "callbacks": { "onChange": [{ "set": "scopes.root.searchTerm", "expr": "evt.value" }] } }
```

Every other scope belongs to a list item or comes from the host. `root` belongs
to the [`<RendererProvider>`](/react/renderer), not to one document, so every
document under one provider shares it. On a chat surface that is what lets
blocks share live state.

## Item scopes

A [list](/entry/fields#list-fields) renders its `component` once per item and
gives **each item its own scope**, named by `as`:

```jsonc
{ "key": "orders", "component": "Card",
  "each": "scopes.root.orders", "as": "order", "keyBy": "id",
  "children": ["order-title"] }
{ "key": "order-title", "component": "Text",
  "props": { "expr": "({ text: (scopes.order.index + 1) + '. ' + scopes.order.item.customer + ' #' + scopes.order.id })" } }
```

Over `[{ id: "a1", customer: "Ada" }, { id: "b2", customer: "Grace" }]` that is
`1. Ada #a1` then `2. Grace #b2`. `item` is the record, `index` its zero-based
position, `id` the key `keyBy` picked (the index when there is no `keyBy`).

**A list is N scopes, not one**, so per-row state like `scopes.order.expanded` is
genuinely per row.

**Scopes stack**, so names must be globally unique. Reusing one does not error —
it silently shadows:

```jsonc
// ❌ the inner `as` overwrites the outer. Inside a line item, `scopes.item` IS
//   the line item, and the order it belongs to is unreachable.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "item", "children": ["lines"] }
{ "key": "lines", "component": "Text", "each": "scopes.item.item.lines", "as": "item",
  "props": { "expr": "({ text: scopes.item.item.sku })" } }

// ✅ distinct names stack — a line item sees root, order and line at once.
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "order", "children": ["lines"] }
{ "key": "lines", "component": "Text", "each": "scopes.order.item.lines", "as": "line",
  "props": { "expr": "({ text: scopes.order.item.id + ' / ' + scopes.line.item.sku })" } }
```

## Reaching across rows

To read *across* rows — a sum, a count — use **`childScopes`**, the array of the
rows' live scopes. The list publishes it *after* it commits, so read it from a
`callbacks` step and park the result on a plain path:

```jsonc
{ "key": "orders", "component": "Card",
  "each": "scopes.root.orders", "as": "order", "keyBy": "id", "children": ["order-title"] }
{ "key": "recount", "component": "Button", "props": { "literal": { "text": "Recount" } },
  "callbacks": { "onClick": [
    { "set": "scopes.root.total",
      "expr": "scopes.root.childScopes.order.reduce((s, o) => s + o.item.total, 0)" }] } }
{ "key": "total", "component": "Text", "props": { "expr": "({ text: scopes.root.total })" } }
```

`childScopes.<as>` lives on the scope *containing* the list. Each entry is itself
a full scope, so the chain continues:
`scopes.root.childScopes.order[0].childScopes.line[0]`.

## Reading and writing

- **Reads** are plain property access inside an [expression](/entry/expressions):
  `scopes.root.count`, `scopes.order.item.total`.
- **Writes happen only through `set`**, on a `seed` or `callbacks`
  [assignment](/entry/value-sources). `seed` initializes a path at mount;
  `callbacks` update it on an event.

A `set` path whose parent is not set throws, so seed the container first:

```jsonc
// ❌ nothing seeded `tags` — this fails instead of guessing a shape
{ "set": "scopes.root.tags.0", "literal": "new" }

// ✅ seed the real array, then replace the whole array.
{ "set": "scopes.root.tags", "literal": [] }                          // in `seed`
{ "set": "scopes.root.tags", "expr": "[...currentValue, evt.value]" } // in a callback
```

Subscriptions run **one way, downward**. A reader is notified when its own path
is written, or any path above it — never a path below it.

```jsonc
{ "set": "scopes.root.rows", "expr": "listRows()" }  // notifies a reader of scopes.root.rows.length
{ "set": "scopes.root.rows.0.qty", "literal": 3 }    // notifies nothing reading scopes.root.rows
```

So **replace the whole array or object**, rather than writing into it. That is
what a mutate-then-refetch callback already produces, and it notifies every
reader below the path. See [Reactivity & Dependencies](/entry/reactivity).

## Lifecycle

A `seed` initializes a path when its element mounts, and it then persists for the
life of the page — through re-renders, and while the element is `hidden`. A path
that was never seeded reads back as `undefined`.

A `seed` is **first-writer-wins**: it assigns only if the path is still
`undefined`.

```jsonc
{ "key": "panel", "component": "Card", "seed": [{ "set": "scopes.root.sort", "literal": "name" }],
  "children": ["label"] }
{ "key": "label", "component": "Text", "seed": [{ "set": "scopes.root.sort", "literal": "price" }],
  "props": { "expr": "({ text: scopes.root.sort })" } }
```

Renders `name`. `panel` seeds before `label` mounts, so `label`'s seed finds the
path defined and writes nothing — a no-op, not an error. The same `set` in a
`callbacks` step would write `price`. This is also why a value the user changed
survives a re-mount instead of snapping back.

State can also come from the host. [`<RendererProvider>`](/react/renderer) takes
two ways in:

```tsx
<RendererProvider
  implementations={allImplementations}
  scopes={{ userCtx: createProxyScope({ id: 7, name: "Ada" }) }}
  init={({ scopes }) => {
    (scopes.root as Record<string, unknown>).theme = "dark";
  }}
>
  <EntriesRenderer entries={entries} />
</RendererProvider>
```

`scopes` adds named containers alongside `root`, captured on mount; entries read
them as `scopes.userCtx.name`. `init` runs once before any entry evaluates and
writes straight through the live proxy — unconditionally, unlike a seed, so a
later `seed` for the same path is a no-op.

Any extra scope you pass must also be described in your system prompt; the
prompt builders only know about `root` and the list scopes.
