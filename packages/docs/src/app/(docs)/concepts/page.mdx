# Concepts

A complete uicast document, four entries. It loads orders from a backend, shows
the count, renders one row each, and refetches on click. Every concept on this
page is in it.

<OrdersExample />

## The tree is built from keys

Nothing is nested in the file. The tree is built from **key references**. `card`
lists `["title","refresh","rows"]`, so those three are its children:

```
card ─┬─ title
      ├─ refresh
      └─ rows  (repeats: one element per order)
```

`card` is the **root** because no other line lists it as a child. This is also
why documents stream top down: a parent must arrive before its children, and until a child's line
arrives the renderer shows a placeholder.

## One line, many elements: lists

The `rows` line has an `each` field, which makes it a **list**. It repeats once
for every item in the array:

```jsonc
{ "each": "scopes.root.orders", "as": "order", "keyBy": "id" }
```

- **`each`** — the array to repeat over, evaluated in the *parent's* scope.
- **`as`** — names the per-item scope. Inside, you read `scopes.order.item`
  (the order), `scopes.order.index` (0, 1, 2 …), and `scopes.order.id`.
- **`keyBy`** — which field that id comes from. `"id"` means `item.id`.

So with three orders in state, one entry produces three elements:

| `scopes.order.item` | `scopes.order.index` | rendered |
|---|---|---|
| `{ id: 7, customer: "Maya", total: 40 }` | `0` | Maya · 40 |
| `{ id: 8, customer: "Jonas", total: 15 }` | `1` | Jonas · 15 |
| `{ id: 9, customer: "Priya", total: 92 }` | `2` | Priya · 92 |


## State lives in scopes

State is a flat set of named reactive containers. This document has two:

- **`scopes.root`** — one per app, shared by every element. Here it holds
  `orders`, put there by the `seed` on line 1.
- **`scopes.order`** — one per row, created by the list's `as`. Line 4 reads
  `scopes.order.item.customer`.

The names are flat — `scopes.order` is not part of `scopes.root` — but an
element still reaches every scope around it. A list inside a list creates an
inner scope, and an element there reads them all:

```jsonc
{ "key": "orders", "each": "scopes.root.orders", "as": "order", "children": ["lines"] }
{ "key": "lines",  "each": "scopes.order.item.lines", "as": "line",
  "props": { "expr": "({ text: scopes.order.item.id + ' / ' + scopes.line.item.sku })" } }
```

That element reads `root`, `order` and `line` at once, which is why every `as`
name must be unique in the document — a repeat silently hides the outer one.
See [State &amp; Scopes](/entry/state).

### Reading the item scopes from above

The `$135 total` sits on the card, outside the list, so it has to reach into the
per-row scopes. A list publishes them to the scope above under
**`childScopes.<as>`**, one entry per item:

```js
scopes.root.childScopes.order   // → [ {item, index, id}, {item, index, id}, {item, index, id} ]
```

The total line just sums `item.total` across them:

```jsonc
{ "key": "total", "component": "Heading", "props": { "expr":
  "({ text: '$' + (scopes.root.childScopes?.order ?? []).reduce((sum, s) => sum + s.item.total, 0) + ' total' })" } }
```

Two details matter:

- **`?.order ?? []` is required.** The key does not exist until the list has
  rendered. Without the guard the element fails into its error slot and stays
  there — it is not retried once `childScopes` appears.
- **It republishes when the list changes, not when one item changes.** Refresh
  replaces `scopes.root.orders`, the rows rebuild, and the total re-runs:
  135 → 160 → 83. A write *inside* one item scope notifies only that item.

So use `childScopes` when a row holds state the source array does not — a
selection, an edited draft — and read it from a **callback**. When the number
is derivable from the array, read the array:
`scopes.root.orders.reduce((sum, o) => sum + o.total, 0)` needs no guard.

## Reading state subscribes to it

Line 2 reads `scopes.root.orders.length`. Nobody declared that dependency — the
engine reads it out of the expression and subscribes the element to that path:

```jsonc
{ "props": { "expr": "({ text: scopes.root.orders.length + ' orders' })" } }
//                                 └── auto-subscribes to scopes.root.orders.length
```

Click **Refresh**, the callback writes `scopes.root.orders`, and the heading and
every row re-render — a write notifies readers of that path and of every path
below it. The button never mentions the heading. See
[Reactivity](/entry/reactivity).

## Expressions compute; `set` changes

`props.expr`, `hidden`, `each`, and the `expr` of any `seed` or `callbacks` step
hold **one JavaScript expression**, evaluated against the scopes. Two rules.

**An expression only computes.** The only way to write state is a step's `set`
field:

```jsonc
{ "expr": "scopes.root.count + 1" }                          // ✅ computes
{ "set": "scopes.root.count", "expr": "currentValue + 1" }   // ✅ computes, then writes
{ "expr": "scopes.root.count = 1" }                          // ❌ rejected: assignment
```

**The same state must give the same result.** Expressions re-run whenever a path
they read changes, so anything random or time-based renders inconsistently:

```jsonc
{ "props": { "expr": "({ id: Math.random() })" } }        // ❌ different every render
{ "seed": [{ "set": "scopes.root.id", "expr": "..." }] }  // ✅ compute once, read the stored value
```

## What makes a document valid

Most render failures are one of these.

**Exactly one root** — the one element whose `key` appears in no other
`children`:

```jsonl
{"key":"a","component":"Card","children":["b"]}   ✅ root
{"key":"b","component":"Text"}                     ✅ referenced once
{"key":"c","component":"Text"}                     ⚠️ second root — nobody references c
```

Several roots will not crash — the renderer wraps them in a fragment — but one
root is the contract.

**A list is never the root.** An entry with `each` needs a parent to repeat
inside:

```jsonl
{"key":"rows","component":"OrderRow","each":"scopes.root.orders","as":"order"}   ⚠️ as the root
{"key":"card","component":"Card","children":["rows"]}                            ✅ wrap it
```

**Scope names must be unique.** Two lists sharing an `as` collide, since scope
names are one flat namespace:

```jsonl
{"key":"orders","each":"scopes.root.orders","as":"row", ...}     ❌ both write scopes.row
{"key":"invoices","each":"scopes.root.invoices","as":"row", ...}
```

**Reactive expressions are synchronous.** `props`, `hidden`, and `each` cannot
call host functions. Those belong in `seed` (on mount) and `callbacks` (on an
event) — the two places the engine awaits a result. Write `listOrders()`, never
`await listOrders()`.

**Re-sending a key is an update, not an error.** The element is replaced in
place. This is how [edit turns](/prompt) work:

```jsonl
{"key":"title","component":"Heading","props":{"expr":"({ text: 'Orders' })"}}
{"key":"title","component":"Heading","props":{"expr":"({ text: 'All orders' })"}}
```

## Vocabulary

Words uicast uses in a specific way. One is narrower than usual: **props**
excludes event handlers — a definition declares `props` and `callbacks`
separately, and an entry sets them as separate fields.

| Term | Meaning |
| --- | --- |
| **uicast document** | One complete UI: a flat set of entries forming a tree with one **root** — the entry no other entry lists in `children`, derived structurally rather than flagged. Streamed as JSONLines, one entry per line. |
| **entry** | One line of that stream: the JSON describing a single node. You author entries; the node that mounts from one is its **element**. See [Component Entry Format](/entry). |
| **list** | An entry that repeats, marked by [`each`](/entry/fields) (the collection) with `as` naming the per-item scope. Each repetition is an **item**, read as `scopes.<as>.item`, `.index`, `.id`. |
| **scope** | A named reactive state bag: `scopes.root` shared across the document, plus one per list item. Scopes stack but never nest. See [State &amp; Scopes](/entry/state). |
| **expression** | A single JavaScript expression evaluated against the scopes — the format's only dynamic surface, guarded by SaferEval: an allow-list plus a static pass, [not a sandbox](/entry/expressions#safety). |
| **value source** | How a value is produced: `{ "literal": … }` verbatim, or `{ "expr": … }` evaluated. See [Value Sources](/entry/value-sources). |
| **definition** / **implementation** | The two halves of a component: the def is what the model reads (`name`, `description`, and `StandardSchemaV1 & StandardJSONSchemaV1` schemas), the impl is the React that draws it. A registered set of pairs is a **catalog**. See [def](/def) and [impl](/react/impl). |
| **host function** | A function the host exposes for expressions to call — async or not; the engine awaits the result either way. Each is a [`standard-tool`](https://standard-tool.js.org/) — name, description, optional `StandardSchemaV1 & StandardJSONSchemaV1` schemas, `execute`. See [Host functions](/functions). |
