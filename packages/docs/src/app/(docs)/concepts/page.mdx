# Concepts

## What the entry format is

The **entry format** is a declarative UI language — components, reactive state,
derived values, conditional rendering, lists, events — in the same family as JSX,
React, or Vue. What sets it apart is *who writes it*. JSX is authored by developers
and optimized for reading, refactoring, and maintenance; the entry format is
authored by a language model and optimized for generation. Every design choice
follows from that one inversion:

| | JSX / React / Vue | Entry format |
|---|---|---|
| Author | human developer | language model |
| Optimized for | reading, refactoring | generation — few tokens, low ambiguity, streaming |
| Components | open — you write them | fixed — chosen from a catalog |
| Logic | arbitrary code | pure expressions over a fixed scope |
| Unit | a component / module | one line (one entry) |
| Output | source → build → deploy | a data stream, rendered directly |

An open-ended language is a feature for a person and a liability for a generator —
more ways to be wrong, to hallucinate an import, to emit code that won't run. So
the entry format spends expressiveness to buy reliability: a flat grammar, a closed
component set, no modules or side effects, and output that is a static asset, not a
codebase. It is **not** a tool that writes React for you to own and deploy — the
model's output *is* the running app.

Each ingredient — JSONLines, sandboxed expressions, reactive state — is familiar;
the language that fuses them into one model-authored, directly-rendered whole is
what's new.

## The model

A **document** is a flat set of **elements** that form a tree. There is exactly
one **root** (the element no other element lists as a child) and every other
element is referenced as a child exactly once. An element carries an identity
(`key`), a `component` to render, and optional `props`, `seed`, `hidden`,
`callbacks`, and `children`.

An element that **repeats** is a **list**: it carries an `each` (the collection)
and an `as` (the per-item scope name). List-ness is structural — an element is a
list iff it carries `each`.

## Expressions

`props`, `hidden`, `each`, and the `expr` of any `seed` / `callbacks`
assignment carry a single JavaScript expression, evaluated against the current
scopes. Two rules:

- **Pure.** An expression computes and returns a value; it must not mutate state
  or cause side effects. State changes happen only through the `set` field of a
  `seed` / `callbacks` assignment.
- **Stateless.** An expression must be a deterministic function of the scopes
  (and `evt` in callbacks) it reads — no `Math.random()`, no clock reads, no
  counter that survives between evaluations. A reactive site re-evaluates
  whenever a scope path it reads changes, so a non-deterministic expression
  renders inconsistently.

## Scopes

State lives in **scopes** — a flat namespace of reactive bags. There is one root
scope (`scopes.root`) and one scope per list item, named by the list's `as`.
Reading a scope path inside a reactive expression auto-subscribes it: when the
path is written, the expression re-evaluates. Producers never declare
dependencies.

Each scope is a self-contained reactive store — a proxied state bag with
path-exact subscriptions — and together with the expression evaluator and
dependency extraction it forms the engine's **framework-neutral core**:
`@ui-fired/core` has no React dependency, and `@ui-fired/react`'s `<Renderer>`
is one binding built over it.
