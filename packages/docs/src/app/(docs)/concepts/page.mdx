# Concepts

A complete **uicast** document, six entries: it loads products, lists them with
an editable quantity, edits one in a modal, and keeps a live total. Every
concept on this page is in it.

<OrdersExample />

## The tree is built from keys

Nothing is nested in the file. `card` lists
`["title","refresh","rows","total","editor"]{:ts}`, so those five are its children:

```
card ─┬─ title
      ├─ refresh
      ├─ rows  (repeats: one element per product)
      ├─ total
      └─ editor  (hidden until a row's ✎ is pressed)
```

`card` is the **root**: no line lists it as a child. A parent must stream
before its children; until a child's line arrives, the renderer shows the
parent's [skeleton](/react#skeleton) in its place.

## One line, many elements: lists

The `rows` line has `each`, which makes it a **list**: it repeats once per item
in the array.

```jsonc
{ "each": "scopes.root.products", "as": "product", "keyBy": "id" }
```

- **`each`** — the array, evaluated in the *parent's* scope.
- **`as`** — names the per-item scope. `scopes.product` is the product itself,
  plus `$$index` (0, 1, 2 …) and `$$id`.
- **`keyBy`** — the field `$$id` comes from.

Three products in state, three elements from one entry:

| `scopes.product` | `scopes.product.$$index` | rendered |
|---|---|---|
| `{ id: 8, name: "Espresso Beans", price: 15, qty: 1 }{:ts}` | `0{:ts}` | Espresso Beans · $15 × 1 |
| `{ id: 9, name: "Pour-Over Kettle", price: 23, qty: 4 }{:ts}` | `1{:ts}` | Pour-Over Kettle · $23 × 4 |
| `{ id: 10, name: "Ceramic Mug", price: 14, qty: 2 }{:ts}` | `2{:ts}` | Ceramic Mug · $14 × 2 |


## State lives in scopes

State is a flat set of named reactive containers. This document has two:

- **`scopes.root`** — one per app, shared by every element. It holds
  `products`, set by the [`seed`](/entry#seed) on line 1.
- **`scopes.product`** — one per row, created by the list's `as`.

The names are flat — `scopes.product` is not inside `scopes.root` — but an
element reads every scope around it. In a list inside a list, it reads them all:

```jsonc
{ "key": "orders", "component": "Card", "each": "scopes.root.orders", "as": "order", "children": ["lines"] }
{ "key": "lines",  "component": "Typography", "each": "scopes.order.lines", "as": "line",
  "props": { "expr": "({ text: scopes.order.id + ' / ' + scopes.line.sku })" } }
```

So every `as` name must be unique: a repeated name hides the outer scope. See
[State &amp; Scopes](/entry/state).

### Editing a row updates the total

The `$135 total` sits outside the list and reads the array:

```jsonc
{ "key": "total", "component": "Heading", "props": { "expr":
  "({ text: '$' + scopes.root.products.reduce((sum, p) => sum + p.price * p.qty, 0) + ' total' })" } }
```

A row's quantity input writes the row's scope:

```jsonc
{ "onQtyChange": [{ "set": "scopes.product.qty", "expr": "evt.value" }] }
```

A row scope is a window onto its element in the array, so this write changes
the product **inside `scopes.root.products`**, and the total recomputes. The
edit dialog's Save replaces the whole array instead; everything reading it
re-renders.

Both edits then call `updateProduct(...){:ts}`, a [host function](/expr/functions)
that persists the change. Save's first step carries a
[`confirm`](/entry/value-sources#callbackvaluesourceassignment); declining skips
it and every step after. The host's
[`fallbackComponents.confirm`](/react/renderer#fallbackcomponents--the-engines-fallback-ui)
draws that dialog for every document.

## Reading state subscribes to it

The `rows` list reads `scopes.root.products` in its `each`. Nothing declares
that dependency: the engine reads it from the expression and subscribes the
element to the field.

```jsonc
{ "key": "rows", "each": "scopes.root.products", "as": "product", "keyBy": "id" }
//                        └── auto-subscribes to scopes.root.products
```

**Refresh** writes `scopes.root.products`, which wakes every reader: the rows
rebuild and the `N products` count updates. The callback never names the
elements it wakes. See [Reactivity](/entry/reactivity).

## Expressions compute; `set` changes

`props.expr`, `hidden`, `loading`, `each`, and the `expr` of every `seed` or `callbacks`
step hold **one expression** in a [subset of JavaScript](/expr). Two rules.

**An expression only computes.** Only a step's `set` writes state:

```jsonc
{ "expr": "scopes.root.count + 1" }                          // ✅ computes
{ "set": "scopes.root.count", "expr": "currentValue + 1" }   // ✅ computes, then writes
{ "expr": "scopes.root.count = 1" }                          // ❌ rejected: assignment
```

**The same state must give the same result.** `props`, `hidden`, `loading` and
`each` re-run only when a path they read changes, so a clock read there goes stale.
Read the clock in a step and store it:

```jsonc
{ "props": { "expr": "({ text: 'Saved at ' + Date.now() })" } }  // ❌ changes with every re-run
{ "set": "scopes.root.savedAt", "expr": "Date.now()" }           // ✅ read once; props read scopes.root.savedAt
```

## Nothing runs on its own

An event runs a callback, the page updates, then it waits. Expressions only
read state. Callbacks write it on an event, seeds once at mount, and nothing
else writes. So one event does a bounded amount of work. The term is
*synchronous reactive*. Turing complete only if you count the user as the
clock.

## What makes a document valid

Most render failures are one of these.

**Exactly one root** — the element whose `key` is in no `children`:

```jsonl
{"key":"a","component":"Card","children":["b"]}    ✅ root
{"key":"b","component":"Typography"}               ✅ referenced once
{"key":"c","component":"Typography"}               ⚠️ second root — nobody references c
```

Several roots render, wrapped in a fragment, but one root is the contract.

**A list belongs in a container.** A list repeats its `component` per item, so
give it a parent:

```jsonl
{"key":"rows","component":"ProductRow","each":"scopes.root.products","as":"product"}   ⚠️ as the root
{"key":"card","component":"Card","children":["rows"]}                                  ✅ wrap it
```

A root list renders, but its rows sit loose at the top level.

**Give every list its own `as`.** The prompt asks for it, and a nested list that
reuses its parent's `as` hides the parent's item:

```jsonl
{"key":"orders","each":"scopes.root.orders","as":"row", ...}
{"key":"lines","each":"scopes.row.lines","as":"row", ...}   ❌ inside it, scopes.row is the line, not the order
```

**Reactive expressions are synchronous.** `props`, `hidden`, `loading` and `each` cannot
call host functions; the engine rejects the call into the element's error slot.
Call them from `seed` and `callbacks`, where the engine awaits the result:
`listProducts(){:ts}`, never `await listProducts(){:ts}`.

**Re-sending a key is an update, not an error.** The element is replaced in
place, which is how [edit turns](/prompt) work:

```jsonl
{"key":"title","component":"Heading","props":{"expr":"({ text: 'Products' })"}}
{"key":"title","component":"Heading","props":{"expr":"({ text: 'All products' })"}}
```

## Vocabulary

Words **uicast** uses in a specific way. **props** is narrower than usual: it
excludes event handlers, which definitions and entries declare separately as
`callbacks`.

| Term | Meaning |
| --- | --- |
| **uicast document** | One complete UI: a flat set of entries forming a tree with one **root** — the entry no other entry lists in `children`, derived structurally rather than flagged. Streamed as JSONLines, one entry per line. |
| **entry** | One line of that stream: the JSON describing a single node. The node that mounts from it is its **element**. See [Entry fields](/entry). |
| **list** | An entry that repeats, marked by [`each`](/entry) (the collection) with `as` naming the per-item scope. Each repetition is an **item**: `scopes.<as>` is the item itself, plus `$$index` and `$$id`. |
| **scope** | A named reactive state bag: `scopes.root` shared across the document, plus one per list item. Scopes stack but never nest. See [State &amp; Scopes](/entry/state). |
| **expression** | A single expression in a subset of JavaScript, evaluated against the scopes — the format's only dynamic surface. Run by [`@uicast/expr`](/expr): a closed grammar, every read checked at run time, no `new Function`. |
| **value source** | How a value is produced: `{ "literal": … }{:ts}` verbatim, or `{ "expr": … }{:ts}` evaluated. See [Value Sources](/entry/value-sources). |
| **step** | One item of a `seed` or a callback: a value source, optionally with a `set` path to write it to. A step that reads what another writes runs after it. See [Entry fields](/entry#callbacks). |
| **definition** / **implementation** | The two halves of a component: the def is what the model reads (`name`, `description`, and `StandardSchemaV1 & StandardJSONSchemaV1{:ts}` schemas), the impl is the React that draws it. A registered set of pairs is a **catalog**. See [def](/def) and [impl](/react). |
| **host function** | A function the host exposes for expressions to call — async or not; the engine awaits the result either way. Each is a [`standard-tool`](https://standard-tool.js.org/) — name, description, optional `StandardSchemaV1 & StandardJSONSchemaV1{:ts}` schemas, `execute`. See [Host functions](/expr/functions). |
