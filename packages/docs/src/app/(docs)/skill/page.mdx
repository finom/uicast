# Agent skill

uicast ships an [Agent Skill](https://agentskills.io) — a folder with a
`SKILL.md` that teaches a coding agent how to integrate uicast into an app:
definitions and implementations, host functions, prompt assembly, mounting,
streaming on both surfaces, and error handling. Point your agent at it and
"add generative UI to this app" becomes a task it knows how to do.

The skill lives at
[`skills/uicast`](https://github.com/finom/uicast/tree/main/skills/uicast) in
the repo. It is a single self-contained file — no network access needed while
the agent follows it — and it deliberately covers only the **developer side**:
the entry format the model emits is delivered to the generation model by the
[assembled prompt](/prompt) at runtime, not by the skill.

## How skills work

Agent Skills is an open format supported by many agents (Claude Code, Cursor,
Codex, Gemini CLI, OpenCode, and [more](https://agentskills.io/home)). An agent
loads only the skill's name and description at startup; when a task matches —
"set up uicast", "let the LLM build the interface" — it reads the full
instructions into context and follows them.

## Claude Code

The repo doubles as a plugin marketplace:

```sh
/plugin marketplace add finom/uicast
/plugin install uicast
```

Or copy the folder for one project (no plugin involved):

```sh
mkdir -p .claude/skills
cp -R path/to/uicast/skills/uicast .claude/skills/uicast
```

Use `~/.claude/skills/` instead to make it available in every project.

## Other clients

Any client that supports Agent Skills reads the same folder. Copy
`skills/uicast` into the location your client discovers skills from — most use
a project-local or user-level `skills` directory; the exact path is in each
client's own documentation (the [client list](https://agentskills.io/home)
links them). Nothing in the skill is client-specific.

## Without skill support

The file is plain Markdown. Paste `SKILL.md` into any agent's context — or
read it yourself; it doubles as the shortest complete integration guide.
