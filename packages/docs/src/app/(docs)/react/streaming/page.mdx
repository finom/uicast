# Streaming

A uicast document is a **stream** — the model emits one [entry](/entry) per
line, and the UI mounts each entry the moment its line completes. Between the
model and the mounted tree there are two hops: your server consumes the model's
output stream, and the browser consumes what your server relays. Both hops are
JSONLines, so core ships one reader for both — `streamJsonLines` — and on the
React side TanStack Query's `streamedQuery` turns that reader into a growing
array your component renders from.

## `streamJsonLines`

```ts
function streamJsonLines<T = unknown>(
  source: ReadableStream<Uint8Array | string> | AsyncIterable<string | Uint8Array>,
): AsyncGenerator<T>;
```

Core's tolerant JSONLines reader, exported from `uicast`. Give it any
line stream — a model SDK's text stream on the server, `response.body` in the
browser — and iterate parsed values as lines complete:

```ts
import { streamJsonLines } from "@uicast/core";

for await (const value of streamJsonLines(source)) {
  // one parsed JSON value per complete line
}
```

Three rules define it:

- **Partial lines buffer.** Chunk boundaries don't align with line boundaries;
  a line split across chunks yields once, when its `\n` arrives. The tail after
  the last newline is flushed at end of stream.
- **Non-JSON lines drop silently.** Models make mistakes — a stray code fence,
  a line of prose, a blank line. Anything `JSON.parse` rejects is skipped, so
  one bad line never poisons the stream.
- **Every valid JSON value yields.** The reader has no opinion about shape.
  `<T>` is a caller assertion — the same trust you place in `res.json() as T` —
  and shape-checking stays at the call site, where it belongs.

## Server: model stream → rows + relay

On the server, the source is the model SDK's text stream. Parse it with
`streamJsonLines`, keep the values that are entries, persist each one, and relay
it to the browser as NDJSON — the entry is stored and on the wire the moment its
line completes, not when the generation finishes:

```ts
import { type ComponentEntry, streamJsonLines } from "@uicast/core";
import { streamText } from "ai";

const isEntry = (value: unknown): value is ComponentEntry =>
  !!value &&
  typeof value === "object" &&
  typeof (value as ComponentEntry).key === "string" &&
  typeof (value as ComponentEntry).component === "string";

export async function POST(req: Request) {
  const { prompt } = await req.json();
  const result = streamText({ model: "openai/gpt-4o", system, prompt });

  const encoder = new TextEncoder();
  const stream = new ReadableStream<Uint8Array>({
    async start(controller) {
      const send = (obj: unknown) =>
        controller.enqueue(encoder.encode(`${JSON.stringify(obj)}\n`));

      for await (const value of streamJsonLines(result.textStream)) {
        if (!isEntry(value)) continue;
        await db.insert(componentEntries).values({ data: value });
        send(value);
      }
      send({ type: "done" });
      controller.close();
    },
  });

  return new Response(stream, {
    headers: { "content-type": "application/x-ndjson; charset=utf-8" },
  });
}
```

The `isEntry` guard is the server's shape check: the model was prompted to emit
only entries, but the reader yields every valid JSON line, and only lines with a
`key` and a `component` belong in the database.

## Browser: `streamedQuery`

TanStack Query ships
[`streamedQuery`](https://tanstack.com/query/latest/docs/reference/streamedQuery)
— a query-function wrapper that consumes an `AsyncIterable` and appends each
yielded value to the cached array, re-rendering the component per chunk. Its
`streamFn` wants exactly what `streamJsonLines` returns:

```tsx
import {
  experimental_streamedQuery as streamedQuery,
  useQuery,
} from "@tanstack/react-query";
import { type ComponentEntry, streamJsonLines } from "@uicast/core";

type ControlLine = { type: "done" } | { type: "error"; error: string };
type Line = ComponentEntry | ControlLine;

const { data: lines = [], isFetching } = useQuery({
  queryKey: ["generate", prompt],
  queryFn: streamedQuery({
    streamFn: async ({ signal }) => {
      const res = await fetch("/api/generate", {
        method: "POST",
        headers: { "content-type": "application/json" },
        body: JSON.stringify({ prompt }),
        signal,
      });
      if (!res.ok || !res.body) throw new Error(`Generation failed (${res.status})`);
      return streamJsonLines<Line>(res.body);
    },
  }),
});

const entries = lines.filter((line): line is ComponentEntry => "component" in line);
```

`data` is the lines received so far — it grows line by line while `isFetching`
stays `true`, and the query settles when the stream ends. Hand the filtered
`entries` straight to the [renderer](/react/renderer): its `entries` prop is
made for append-only growth, and settled subtrees don't re-render as later
entries arrive.

```tsx
<Renderer implementations={allImplementations} entries={entries} />
```

## Control lines

The reader carries no protocol — entries and whatever else your endpoint sends
ride the same stream as plain JSON values. The example above mixes entries with
an app-defined envelope (`{ type: "done" }`, `{ type: "error" }`); the client
discriminates with one check (`"component" in line`) and the envelope's shape
stays entirely yours. Keep expected mixed-shape streams typed as a union and
narrow at the call site — don't teach the reader your protocol.
