# Renderer

The React binding is two pieces. `<RendererProvider>` is the **host side**: it
carries your [component implementations](/react/impl), the
[host functions](/functions), the engine's fallback UI — and **one shared
reactive store** for everything beneath it. `<EntriesRenderer>` is the **mount
point**: give it a stream of [entries](/entry) and it renders the entry tree
into live React, evaluating every expression against that shared state and
re-rendering each node as the state changes.

Both are exported from `@uicast/react`. This is the **host** side of the
engine; the [entry format](/entry) is what the model produces for it.

## Mounting a document

```tsx
import { EntriesRenderer, RendererProvider } from "@uicast/react";
import { allImplementations } from "@uicast/shadcn-catalog/impls";

<RendererProvider implementations={allImplementations} functions={hostFunctions}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

That is the whole contract. The provider builds a `name → implementation`
lookup and creates the group's **root scope**; the renderer walks the entries
in tree order and mounts each one — evaluating its `props`, `hidden`, `seed`,
and `callbacks` against that scope.

## One store, many renderers

Every `<EntriesRenderer>` under the same provider renders against the **same
`root` scope**. A write in one document — a callback assignment, a seed — is
live in every other document that reads the path:

```tsx
<RendererProvider implementations={allImplementations} functions={hostFunctions}>
  <EntriesRenderer entries={ordersBlock} />   {/* seeds scopes.root.orders */}
  <EntriesRenderer entries={statsBlock} />    {/* reads scopes.root.orders — live */}
</RendererProvider>;
```

This is what makes chat surfaces coherent: each ```` ```uicast ```` block in a
conversation is its own `<EntriesRenderer>`, and together they behave as **one
app** — the same path means the same data in every block (see
[Streamdown plugin](/streamdown)). Seeds use first-writer-wins semantics
(`default: true`), so a repeated seed never clobbers state that already exists —
which is why the fence prompt makes every block seed everything it reads: a
no-op in the chat, and the block still works extracted as a standalone page.

To *isolate* documents instead, give each its own provider.

## `RendererProvider` props

- **`implementations`** — the [`ComponentImplementation`](/react/impl) array the entries
  can mount, partner to the def [registration](/def#registration). On a duplicate
  `name` the **later entry wins** (`[...allImplementations, MyCard]` replaces the
  catalog's `MyCard`) and a `console.error` is logged. `RootFragment` is
  **reserved**: the provider merges its own host implementation in under that
  name *after* your array, so one you name `RootFragment` is silently replaced.
- **`functions`** *(optional)* — a `StandardToolV0[]`
  ([standard-tool](https://standard-tool.js.org/): each entry a `name`, a
  `description`, optional input/output schemas, and an `execute`). They are
  exposed as **bare identifiers** to every expression the engine evaluates, though the contract scopes calls to
  [`seed`](/entry/fields#seed) and [`callbacks`](/entry/fields#callbacks),
  written `name(input)`: `props` and `hidden` evaluate synchronously during
  render, so the prompt forbids host calls there. This is how a generated UI
  reaches your API — see [Host functions](/functions).
- **`defaultComponents`** *(optional)* — the engine's fallback UI; see
  [below](#defaultcomponents--the-engines-fallback-ui).
- **`allowedGlobals`** *(optional)* — extra expression globals; see
  [below](#allowedglobals--extend-the-expression-allow-list).
- **`init`** *(optional)* — a one-shot side effect for the whole group: it runs
  once, when the first `<EntriesRenderer>` mounts, before its entries evaluate.
  It receives `{ scopes }` and may seed `scopes.root.*`; a returned Promise
  suspends the awaiting renderers until it resolves. Use it to preload state
  the documents read — see [State &amp; Scopes](/entry/state).
- **`onError`** *(optional)* — called once per classified failure: every failure
  the `error` slot shows, **plus callback failures, which never render a slot**
  (a callback doesn't render, so `onError` is its only channel). It receives the
  same `EntryError`. Branch on `error.fault`: `"document"`
  means the model's output is at fault and a recovery re-emission can fix it;
  `"environment"` means host code failed. See
  [Error recovery § Classification](/error-recovery#classification-entryerror-and-onerror).
- **`scopes`** *(optional)* — extra named scopes exposed alongside `root`, for
  host context the documents may read (`scopes.userCtx.…`). Each value must be a
  reactive scope built with [`createProxyScope`](/core#scopes) — a plain object
  has no `$set` / `$emitter`. Captured on mount, so build it at module scope.

`<EntriesRenderer>` takes one prop: **`entries`** — the
[`ComponentEntry`](/entry) lines to render, in tree order. Pass a **new array**
as lines stream in (`[...entries, next]`) — `<EntriesRenderer>` is memoized on
the `entries` reference, so an in-place `push` renders nothing. Settled subtrees
don't re-render as later entries arrive.
It must be rendered inside a `<RendererProvider>` and throws a clear error
otherwise.

### Pass stable references

`implementations` and `functions` feed a React context whose identity must stay
stable, or **every node re-renders**. Define them as module constants (or
memoize) — never an inline `[...]` or `Object.values(...)` rebuilt each render.

```tsx
const implementations = [...allImplementations, MyCard]; // module scope ✓
const functions = [saveRow, deleteRow]; //                   module scope ✓
```

### `defaultComponents` — the engine's fallback UI

The slots the engine renders on its own behalf, distinct from `implementations`
(the components the model names). Three are wired:

| Slot | Rendered when | Default if omitted |
|---|---|---|
| `placeholder` | a child hasn't streamed in yet, an async [`seed`](/entry/fields#seed) is resolving, or an async `init` is still pending (that one covers the whole group) | nothing — the pending node stays empty |
| `confirm` | a callback step carries `confirm:` — the modal that gates it | `window.confirm` |
| `error` | any element-level failure: an implementation throws, an expression fails, an entry is misused as a list, or its `component` has no implementation | bare inline-styled `div` |

Each slot is optional; supply only the ones you want to style. The `confirm`
and `error` defaults keep the engine renderable with **zero UI dependencies**;
the catalog ships polished versions — `ConfirmModal`, `RenderError` — that you
wire in explicitly:

```tsx
import { EntriesRenderer, RendererProvider } from "@uicast/react";
import {
  ConfirmModal,
  RenderError,
} from "@uicast/shadcn-catalog/default-components";

<RendererProvider
  implementations={allImplementations}
  defaultComponents={{
    confirm: ConfirmModal,
    error: RenderError,
  }}
>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

Like `implementations`, pass a **stable reference**: it folds into the same
context.

To author your own slot, match the props the engine hands it — both types are
exported from `@uicast/react`:

```ts
type ConfirmComponentProps = {
  open: boolean;      // the dialog is always mounted; this toggles it
  message: string;    // the callback step's `confirm:` text
  onConfirm: () => void;
  onCancel: () => void;
};

type ErrorComponentProps = {
  error: EntryError;      // classified: switch on `error.reason` / `error.fault`
  elementKey?: string;    // set when the failure is tied to a specific entry
};
```

Every failure arrives as an [`EntryError`](/error-recovery#classification-entryerror-and-onerror)
— an unknown component name included, as `reason: "unknown-component"` — so one
`error` component can show case-specific UI by switching on `error.reason`.

`confirm` is a **controlled** dialog — always mounted, shown by `open` — so your
component holds no open/closed state of its own; the engine owns it. The
`placeholder` slot takes **no props** (`() => ReactElement`).

### `allowedGlobals` — extend the expression allow-list

Expressions may reference only a fixed [safe set of globals](/entry/expressions#safety)
(`Math`, `JSON`, `Date`, …); anything else is rejected before it runs.
`allowedGlobals` **adds** to that set — benign globals the default list omits:

```tsx
<RendererProvider
  implementations={allImplementations}
  allowedGlobals={["structuredClone", "crypto"]}
>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

It is **additive only**: it cannot re-enable the capability globals the engine
shadows (`fetch`, `Function`, `setTimeout`, …), which stay blocked whatever you
list. See [Safety](/entry/expressions#safety) for the full model.
