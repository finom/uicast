# Component implementation

A component is a **pair**: a [definition](/def) the model reads, and an
implementation React runs. The def says what the component is; the impl decides
what it renders, usually by wrapping a real React component.

```tsx filename="src/uicast/badge/impl.tsx"
import { createComponentImplementation } from "@uicast/react";
import { Badge } from "./badge";
import { BadgeDef } from "./def";

export const BadgeImpl = createComponentImplementation({
  def: BadgeDef,
  render: ({ text, children, variant }) => (
    <Badge variant={variant}>{children ?? text}</Badge>
  ),
});
```

`createComponentImplementation` comes from `@uicast/react`, not core — core stays
framework-agnostic. It takes the `def` and a `render` function and returns the
implementation you register.

## The render function

`render` receives a single argument, **typed against the def**:

- **props** — inferred from the def's `props` schema, already **resolved**: the
  engine evaluates the entry's [`props`](/entry/fields#props) value source
  against state, parses the result through that schema, and hands you its
  output. You never see an expression, and every `.default()` is already
  applied.

  ```jsonc
  { "key": "total", "component": "Text", "props": { "expr": "({ text: 'Open: ' + scopes.root.open })" } }
  // render receives { text: "Open: 3", generatedKey: "total" }
  // …and is called again with "Open: 4" the moment something writes scopes.root.open
  ```

  An implementation is a plain function of its props. It holds no engine state.
- **callbacks** — one `(payload) => Promise<void>` per key in the def's
  `callbacks`, always present even if the entry wired none. Calling one runs that
  entry's [callback steps](/entry/fields#callbacks) with `evt` bound to your
  payload, parsed through the same schema.
- **`children`** — the rendered child elements, present only when the entry has a
  `children` array. It is never a prop — a def declaring one
  [throws](/def#props--the-contract-with-the-model).
- **`generatedKey`** — the entry's `key`, yours to use or ignore. The engine
  never reads it back. The shadcn catalog puts it on the outermost node as
  `data-key`, which a "click an element to revise it" tool can use.

```tsx filename="src/uicast/search-input/impl.tsx"
export const SearchInputImpl = createComponentImplementation({
  def: SearchInputDef,
  render: ({ value, onChange, onClear, onKeyDown }) => (
    <div>
      <Input
        value={String(value ?? "")}
        onChange={(e) => onChange({ value: e.target.value })}
        onKeyDown={(e) => onKeyDown(pickKeyboardEvent(e))}
      />
      <button onClick={() => onClear()}>clear</button>
    </div>
  ),
});
```

`onChange({ value: … })` passes exactly the shape the def declared, which is why
the model's `evt.value` resolves. A React event object is not a payload, so a
shared event needs narrowing to the declared fields first — `pickKeyboardEvent`
above is a local helper doing exactly that, one line per field in the
[common-event schema](/def#callbacks--event-payloads).

## Placeholder

An optional `placeholder` fills a component's **content** while something is
still missing. Three cases, all inside an already-mounted parent:

- a child entry has not streamed in yet — the **parent's** placeholder fills the
  empty slot, since the missing child has no implementation to ask;
- the element's own `seed` is still running, when it calls an async host
  function;
- the group's [`init`](/react/renderer#init--preload-state-for-the-group) is
  still running, which fills every pending slot in the group at once.

A component's placeholder never covers its own arrival — that gap belongs to its
parent.

```tsx filename="src/uicast/card/impl.tsx"
export const CardImpl = createComponentImplementation({
  def: CardDef,
  render: ({ title, children }) => <Card title={title}>{children}</Card>,
  placeholder: () => <Skeleton className="h-40" />,
});
```

```jsonc
// while getSales() is in flight, CardImpl's placeholder replaces the Card's
// children — the Card itself, "Sales" heading and all, is already on screen
{ "key": "panel", "component": "Card", "props": { "literal": { "title": "Sales" } },
  "seed": [{ "set": "scopes.root.sales", "expr": "getSales()" }], "children": ["chart"] }

// once the seed settles, a "chart" line that hasn't streamed in yet leaves an
// empty slot — filled by CardImpl's placeholder again, since the gap is the parent's
{ "key": "chart", "component": "BarChart",
  "props": { "expr": "({ data: scopes.root.sales, xKey: 'month', yKeys: ['total'] })" } }
```

`BarChartImpl`'s own placeholder shows in neither case. A per-implementation
`placeholder` beats the global
[`fallbackComponents.placeholder`](/react/renderer); with neither, the pending
element renders nothing.

## Registration

Collect every implementation into the array passed to
`<RendererProvider implementations={...}>`. That is the partner to the def's
[definitions array](/def#registration): defs drive the prompt, implementations
drive rendering. Adding a component means updating both.
