# Component implementation

A component is a **pair**: a [definition](/def) the model reads, and an
implementation React runs. The def says what the component is; the impl decides
what it renders — a wrapper over a component from your design system, or plain
markup.

```tsx filename="src/uicast-catalog/badge/impl.tsx"
import { createComponentImplementation } from "@uicast/react";
import { Badge } from "./badge";
import { BadgeDef } from "./def";

export const BadgeImpl = createComponentImplementation({
  def: BadgeDef,
  render: ({ text, children, variant }) => (
    <Badge variant={variant}>{children ?? text}</Badge>
  ),
});
```

`createComponentImplementation` comes from `@uicast/react`. It takes the `def`
and a `render` function and returns the implementation you register:
`{ def, placeholder }`. The renderer accepts only objects this function made; a
copy or a hand-built object throws at `<RendererProvider>`.

## The render function

`render` receives two arguments. The first is **typed against the def**:

- **props** — inferred from the def's `props` schema, already **resolved**: the
  engine evaluates the entry's [`props`](/entry#props) value source
  against state, parses the result through that schema, and hands you its
  output. You never see an expression, and every `.default()` is already
  applied.

  ```jsonc
  { "key": "total", "component": "Typography", "props": { "expr": "({ text: 'Open: ' + scopes.root.open })" } }
  // render receives { text: "Open: 3" }
  // …and is called again with "Open: 4" the moment something writes scopes.root.open
  ```

  An implementation is a plain function of its props. It holds no engine state.
- **callbacks** — one `(payload) => Promise<void>` per key in the def's
  `callbacks`, always present even if the entry wired none. Calling one runs that
  entry's [callback steps](/entry#callbacks) with `evt` bound to your
  payload, parsed through the same schema.
- **`children`** — the rendered child elements, present only when the entry has a
  `children` array. It is never a prop — a def declaring one
  [throws](/def#props--the-contract-with-the-model).

The second argument is the **render context**, everything that is not a prop or
a callback:

- **`entry`** — the document line being rendered. `entry.key` is the element's
  key, yours to use or ignore; the engine never reads it back. The shadcn
  catalog puts it on the outermost node as `data-key`, which a "click an
  element to revise it" tool can use.
- **`loading`** — the entry's [`loading`](/entry#loading) expression,
  evaluated. Components that show data render busy while it is true: the
  catalog dims the current content in place (`aria-busy`) on tables, cards,
  stats and charts. Controls ignore it.
- **`scopes`** — the scopes the entry's expressions read (`scopes.root`, and
  the item scope of an enclosing list). Read-only from here; state changes go
  through callbacks.

```tsx filename="src/uicast-catalog/search-input/impl.tsx"
export const SearchInputImpl = createComponentImplementation({
  def: SearchInputDef,
  render: ({ value, onChange, onClear, onKeyDown }) => (
    <div>
      <Input
        value={String(value ?? "")}
        onChange={(e) => onChange({ value: e.target.value })}
        onKeyDown={(e) => onKeyDown({ key: e.key, repeat: e.repeat })}
      />
      <button onClick={() => onClear()}>clear</button>
    </div>
  ),
});
```

`onChange({ value: … })` passes exactly the shape the def declared, which is why
the model's `evt.value` resolves. A React event object is not a payload, so
narrow it to the declared fields yourself — the `onKeyDown` handler builds
`{ key, repeat }` by hand, one entry per field in the
[common-event schema](/def#callbacks--event-payloads).

## Placeholder

An optional `placeholder` fills a component's **content** while something is
still missing. Two cases, both inside an already-mounted parent:

- a child entry has not streamed in yet — the **parent's** placeholder fills the
  empty slot, since the missing child has no implementation to ask;
- the element's own `seed` is still running, when it calls an async host
  function.

The placeholder is passed `{ reason: "streaming" | "seeding" }` — the two cases
above — so one function can draw a different loader for each.

A placeholder is also passed `children` — the drawn children of the element —
which can be used to build a document skeleton.

(A pending group [`init`](/react/renderer#init--preload-state-for-the-group)
suspends whole documents behind the global `fallbackComponents.placeholder`
only — per-component placeholders play no part there.)

```tsx filename="src/uicast-catalog/card/impl.tsx"
export const CardImpl = createComponentImplementation({
  def: CardDef,
  render: ({ title, children }) => <Card title={title}>{children}</Card>,
  placeholder: () => <Skeleton className="h-40" />,
});
```

```jsonc
// while getSales() is in flight, CardImpl's placeholder replaces the Card's
// children — the Card itself, "Sales" heading and all, is already on screen
{ "key": "panel", "component": "Card", "props": { "literal": { "title": "Sales" } },
  "seed": [{ "set": "scopes.root.sales", "expr": "getSales()" }], "children": ["chart"] }

// once the seed settles, a "chart" line that hasn't streamed in yet leaves an
// empty slot — filled by CardImpl's placeholder again, since the gap is the parent's
{ "key": "chart", "component": "BarChart",
  "props": { "expr": "({ data: scopes.root.sales, xKey: 'month', yKeys: ['total'] })" } }
```

`BarChartImpl`'s own placeholder shows in neither case. A per-implementation
`placeholder` beats the global
[`fallbackComponents.placeholder`](/react/renderer); with neither, the pending
element renders nothing.

## Registration

Collect every implementation into the array passed to
`<RendererProvider evaluator={evaluator} implementations={...}>`. That is the partner to the def's
[definitions array](/def#registration): defs drive the prompt, implementations
drive rendering. Adding a component means updating both.

## Props the document controls

Every prop value comes from a document a model wrote, and the implementation
is the last code to touch it before the DOM. The [evaluator](/expr) has
already checked the expression; what it cannot check is what your JSX does
with the result. Three rules keep a catalog safe:

- **URLs go through declared URL props.** Never render a plain string prop
  into `src`, `href`, or `poster`. Declare the prop as a URL in the
  [definition](/def) (`z.url()`), and the renderer's
  [`urlPolicy`](/react/renderer#urlpolicy--the-urls-a-document-may-load)
  gates it before your `render` ever runs. An implementation that builds a
  URL from an ordinary string prop bypasses that gate entirely.
- **No document strings in script-capable sinks.** `dangerouslySetInnerHTML`,
  `<style>` text, `srcDoc`, and `on*` attribute strings can carry script — and
  a raw CSS string can exfiltrate via `url(...)`. Style *objects* with fixed
  keys are fine (`style={{ width: props.width }}`); handing the document a
  whole CSS or HTML string is not.
- **Event payloads are plain fields, never the event.** Pass a picked object
  (`onClick(pickMouseEvent(e))` — the catalog's own pattern), not the React
  event. The membrane refuses live objects as a backstop, but the contract is
  yours: everything entering a document's scope is plain, JSON-shaped data.

The shipped catalog follows all three. If you build your own, these rules are
what makes the [security model](/security) hold end to end.
