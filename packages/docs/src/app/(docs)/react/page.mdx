# Component implementation

A component is a **pair**: a [definition](/def) the model reads and an
implementation React runs. The implementation decides what renders: a component
from your design system, or plain markup.

```tsx filename="src/uicast-catalog/badge/impl.tsx"
import { createComponentImplementation } from "@uicast/react";
import { Badge } from "./badge";
import { BadgeDef } from "./def";

export const BadgeImpl = createComponentImplementation({
  def: BadgeDef,
  render: ({ text, children, variant }) => (
    <Badge variant={variant}>{children ?? text}</Badge>
  ),
});
```

`createComponentImplementation` takes the `def` and a `render` function and
returns `{ def, placeholder }`, the object you register. The renderer accepts
only objects this function made; a copy or a hand-built object throws at
`<RendererProvider>`.

## The render function

`render` gets two arguments. The first is typed from the def:

- **props**, already resolved: the engine evaluates the entry's
  [`props`](/entry#props) and parses the result through the def's schema, so
  every `.default()` is applied.

  ```jsonc
  { "key": "total", "component": "Typography", "props": { "expr": "({ text: 'Open: ' + scopes.root.open })" } }
  // render receives { text: "Open: 3" }
  // …and is called again with "Open: 4" the moment something writes scopes.root.open
  ```
- **callbacks**, one `(payload) => Promise<void>` per key in the def's
  `callbacks`, present even if the entry wired none. Calling one parses the
  payload through its schema and runs the entry's
  [callback steps](/entry#callbacks) with it as `evt`.
- **`children`**, the rendered child elements, present only when the entry has
  a `children` array. It is never a prop
  ([a def declaring one throws](/def#props--the-contract-with-the-model)).

The second is the **render context**:

- **`entry`**, the entry being rendered. `entry.key` is yours to use; the engine
  never reads it back.
- **`loading`**, the entry's [`loading`](/entry#loading) expression, evaluated.
  A component that shows data renders busy while it is true; controls ignore it.
- **`scopes`**, the scopes the entry's expressions read: `scopes.root` and the
  item scope of an enclosing list. Read-only here; state changes go through
  callbacks.

```tsx filename="src/uicast-catalog/search-input/impl.tsx"
export const SearchInputImpl = createComponentImplementation({
  def: SearchInputDef,
  render: ({ value, onChange, onClear, onKeyDown }) => (
    <div>
      <Input
        value={String(value ?? "")}
        onChange={(e) => onChange({ value: e.target.value })}
        onKeyDown={(e) => onKeyDown({ key: e.key, repeat: e.repeat })}
      />
      <button onClick={() => onClear()}>clear</button>
    </div>
  ),
});
```

Build each payload from the React event by hand, with exactly the fields its
[schema](/def#callbacks--event-payloads) declares.

## Placeholder

An optional `placeholder` fills a component's **content** while something is
missing. It gets a `reason`:

- `"streaming"`: a child entry has not arrived yet. The **parent's** placeholder
  fills the slot, since the child's component is not known yet.
- `"seeding"`: the element's own `seed` is waiting on an async host function.

It may also get `children`, the element's drawn children, for building a
document skeleton. A pending group
[`init`](/react/renderer#init--preload-state-for-the-group) shows only the
global `fallbackComponents.placeholder`.

```tsx filename="src/uicast-catalog/card/impl.tsx"
export const CardImpl = createComponentImplementation({
  def: CardDef,
  render: ({ title, children }) => <Card title={title}>{children}</Card>,
  placeholder: () => <Skeleton className="h-40" />,
});
```

```jsonc
// while getSales() is in flight, CardImpl's placeholder replaces the Card's
// children — the Card itself, "Sales" heading and all, is already on screen
{ "key": "panel", "component": "Card", "props": { "literal": { "title": "Sales" } },
  "seed": [{ "set": "scopes.root.sales", "expr": "getSales()" }], "children": ["chart"] }

// once the seed settles, a "chart" line that hasn't streamed in yet leaves an
// empty slot — filled by CardImpl's placeholder again, since the gap is the parent's
{ "key": "chart", "component": "BarChart",
  "props": { "expr": "({ data: scopes.root.sales, xKey: 'month', yKeys: ['total'] })" } }
```

`BarChartImpl`'s placeholder shows in neither case. An implementation's
`placeholder` overrides the global
[`fallbackComponents.placeholder`](/react/renderer); with neither, a pending
element renders nothing.

## Registration

Pass every implementation to `<RendererProvider implementations={...}>`; the
[definitions](/def#registration) go to the prompt. Adding a component means
updating both.

## Props the document controls

Every prop comes from a document a model wrote, and the implementation is the
last code between it and the DOM. The [evaluator](/expr) checks the expression,
not what your JSX does with the result. Three rules:

- **URLs go through declared URL props.** Never render a plain string prop into
  `src`, `href` or `poster`. Declare the prop as a URL in the
  [definition](/def) (`z.url()`), and the renderer's
  [`urlPolicy`](/react/renderer#urlpolicy--the-urls-a-document-may-load) checks
  it before `render` runs. A URL built from an ordinary string prop skips that
  check.
- **No document strings in script-capable sinks.** `dangerouslySetInnerHTML`,
  `<style>` text, `srcDoc` and `on*` attribute strings can carry script, and a
  raw CSS string can send data out through `url(...)`. A style object with
  fixed keys is fine (`style={{ width: props.width }}`); a whole CSS or HTML
  string from the document is not.
- **Event payloads are plain fields, never the event.** The membrane refuses
  live objects as a backstop, but the contract is yours: everything that enters
  a scope is plain, JSON-shaped data.

The reference catalog follows all three. The [security model](/security) holds
end to end only if your own implementations do too.
